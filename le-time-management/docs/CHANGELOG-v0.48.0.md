# v0.48.0 版本说明

> 发布日期：2026-09-17
> 改动类型：minor（新增功能 + 界面调整 + bug 修复）
> 本版包含八个未提交批次：**① 局域网联动修复**、**② 更新检测的可见性修复**、**③ 系统托盘与关闭行为设置（新功能，仅桌面）**、**④ 插件管理全量多选与批量启停**、**⑤ 新插件「轮换值日」（dorm-duty）**、**⑥ 轮换值日支持多套轮换（宿舍 / 公区各一套，互不影响）**、**⑦ 界面缩放设置（全界面等比缩放 80%~150%）**、**⑧ 修复任务详情抽屉里多出一行 `null`**。按「未提交批次并入本版、不硬造版本号」的约定合并记录。

## 改了什么

### 批次一 · 局域网联动（设置 → 局域网联动）

1. **修复：「停止服务」按了无反应**（bug 修复）
   - 根因在前端：`lanStop()` 成功后直接 `renderLan()`，但本地 `lanStatus` 仍是
     `{running: true, ...}`，重渲染出来的还是「运行中」的完整 UI，看起来就是没反应。
   - 现在停止成功后先更新 `lanStatus = { running: false }` 再重渲染，并 toast「联动服务已停止」；
     停止失败会 toast 具体错误，不再静默。
   - 后端 `lan_stop` 加固：发出哑请求唤醒服务线程后，轮询等待监听端口真正释放（最多 ~1.5s）
     才返回，避免「停止 → 立刻启动」撞上端口占用报「端口 启动失败」。

2. **新增「从浏览器打开」按钮**
   - 与「复制链接」「停止服务」并排，点击用系统默认浏览器打开联动链接（走 `openExternal`，
     失败时回退 `window.open`），不用再手动复制粘贴。

3. **卡片下方新增状态显示区**
   - 运行中：`状态 ● 运行中`（mint 色强调）+ `端口` + `本机地址`（LAN IP），
     下附提示「手机需与电脑处于同一 Wi-Fi / 局域网，扫码或打开链接即可配对联动」。
   - 已停止：`状态 ○ 已停止` + 端口，下附启动引导提示。
   - 两种状态都有内容，不再是一片空白。

### 批次二 · 更新检测的可见性修复

修的是「更新检测的可见性」：状态回显补上**检查时刻**，并给 GitHub API 请求加
`Cache-Control: no-cache`。两处都不改更新算法本身 —— 算法已验证正确
（v0.45.1 客户端对着线上 v0.46.0 应判 `has_update=true`，Windows 挑
`LeTime-0.46.0-x64-setup.exe`、Android 挑 `LeTime-0.46.0-universal.apk`）。

**背景**（实测时间线，北京时间 2026-09-16/17）：

| 时刻 | 事件 | `releases/latest` 实际返回 |
|---|---|---|
| 01:19 | release 被创建（草稿） | v0.45.1（**草稿不计入 latest**） |
| 01:40 | release 正式发布 | v0.46.0 |
| **02:04:49** | 用户运行的 v0.45.1 完成一次**启动静默检查**（`settings.update.lastCheckAt` 实测值） | v0.46.0 |
| 02:08 | 用户截图，面板仍写「已是最新版本（v0.45.1）」 | v0.46.0 |

那次检查是**成功**的（`lastCheckAt` 只在拿到合法响应后才写），且发生在正式发布之后 24 分钟 ——
不能用草稿窗口解释。`update.rs` 的版本比较逻辑逐行核对无误；一次成功的检查拿到旧 tag，
只能归因于**上游那一刻返回了陈旧版本号**（Fastly CDN：`releases/latest` 响应头
`cache-control: public, max-age=60, s-maxage=60`，刚发版一分钟内可能仍被旧缓存顶住）。
另有一层产品坑：面板不写检查时刻，用户无法分辨「刚查过」还是「几十分钟前的结果」。

改动：

- **状态回显带检查时刻**（`src/updateChecker.js`）：新增会话级 `checkedAt`，
  只在**成功**检查后写入（失败不覆盖）。文案变为「已是最新版本（v0.45.1） · 02:08 检查」／
  「发现新版本 v0.46.0，当前 v0.45.1 · 02:09 检查」；跨天则显示 `M-D HH:MM`。
- **「尚未检查」也给线索**（`src/views/settings/update.js`）：
  显示持久化的「上次自动检查 01:20」时刻（`settings.update.lastCheckAt`）。
- **API 请求加 `Cache-Control: no-cache`**（`src-tauri/src/update.rs`）：
  强制 CDN 回源，发版后点「检查更新」必中最新。

### 批次三 · 系统托盘与关闭行为设置（新功能）

> 影响端：**仅桌面（Windows / Linux / macOS）**，Android 与小程序无任何变化。

1. **系统托盘（桌面端）**
   - 启动后在系统托盘区（Windows 任务栏右下角）显示应用图标。
   - **左键**点托盘图标：显示 / 隐藏主窗口切换。
   - **右键**托盘图标：弹出菜单
     - 「显示主窗口」：把主窗口还原到前台；
     - 「退出 Le时间管理」：退出前先广播 `app-quit` 事件让前端把 350ms 防抖中的数据落盘，再延迟 800ms 退出，不丢最后几秒的编辑。

2. **「点关闭按钮时」设置**（设置 → 界面与交互，仅桌面端显示）
   - **直接退出应用**（默认，与旧版行为一致）；
   - **隐藏到系统托盘**：点关闭按钮只隐藏窗口，应用继续在托盘运行（提醒、局域网联动、定时任务等后台功能不受影响），从托盘左键或右键菜单恢复。

实现说明：

- 行为存放在 `data.json` 的 `settings.closeToTray`（默认 `false`）。Rust 在 `CloseRequested` 事件里**每次现读文件**而非启动时缓存，设置改完立即生效，无需重启。
- 托盘使用打包内嵌的应用图标（`bundle.icon`），菜单 API 为 tauri 2 的 `tray-icon` feature（该 feature 由 tauri 自身按桌面平台门控，Android 构建不受影响）。
- 单实例逻辑同步适配：二次启动仍会把隐藏到托盘的窗口唤回前台。

### 批次四 · 插件管理：全量多选 + 批量启停（设置 → 插件管理）

改动前只有**用户插件**有勾选框（内置插件那一位是空位），批量操作也只有「导出所选 / 删除所选」——
想一口气关掉几个内置插件只能一个个点开关。现在：

1. **勾选框覆盖全部插件**（含内置）
   - 「不能删」只限制删除与导出，不再等于「不能选」。内置插件也能勾上，用于批量启停；
     卡片 title 与 `aria-label` 会说明这个插件能不能删。
2. **新增「开启所选 / 关闭所选」**
   - 走 `pluginHost.setEnabled()`（真正加载 / 卸载插件，不是只改存储），且**只翻转状态确实不同的那些** ——
     已经开着的不会再被重载一遍。
   - 结束 toast 汇报实际翻转了几个；一个都不需要翻转时明确提示「都已开启 / 都已关闭」，不假装做了事。
3. **「删除所选」仍只作用于用户插件**
   - 只勾了内置插件时按钮保持禁用；选择里混了内置插件时，确认框会说明「N 个内置插件不能删除，会被跳过，
     可以改用『关闭所选』」。
4. **「导出所选」跳过内置插件并如实汇报**
   - 选择里只有内置插件时提示「内置插件不能导出，请勾选用户插件」；混选时导出用户插件并提示跳过了几个。
5. **「全选」范围放开到全部插件**（原按钮叫「全选用户插件」），因为批量启停对内置与用户插件都有效。
6. **工具栏右侧新增选择计数**（「未选择 · 共 N 个插件」/「已选 N / 总数」）。

两处性能/手感修复（都是这次才暴露出来的）：

- **勾选不再整页重渲染。** 原实现每个勾选框 `onchange` 都调 `rerender()` —— 重建整个设置页
  （11 个分区全部 DOM），插件多时明显卡顿，还会把滚动位置弹回顶部。现在勾选只调 `paintToolbar()`
  刷新计数与按钮可用态。
- **批量期间压住整页重建。** `setEnabled()` 每次都会 `emitNavChanged()`，而设置页订阅了它并整页重渲染 ——
  批量关 12 个插件就是 12 次全页重建。现在批量循环期间置位 `pluginBatchBusy`，`onNavChanged`
  回调跳过重建，批量结束自己重建一次。

实现说明：选择集 `selectedPlugins` 由「仅用户插件」放开为全量，清理失效 id 时对着 `regs` 而不是 `userRegs`；
批量启停用 `try/finally` 复位守卫，中途抛错也不会把设置页永久锁死在「不重渲染」状态。

### 批次七 · 界面缩放设置（设置 → 界面与交互）

「手机上看不清」「一屏想多放点内容」—— 这类诉求原先只能靠系统级缩放，应用内没有出口。
本批新增**全界面等比缩放**：一个 80%~150% 的滑块，把整页（文字、卡片、间距、图标、按钮）
按同一比例一起缩放，三端都生效。

1. **滑块 + 预设 + 实时预览**
   - 范围 80%~150%、步进 5%，四枚快捷预设（80% / 标准 / 125% / 150%）。
   - 拖动时**实时预览不落盘**（`{ persist: false }`），松手（`change`）才归一化并写入偏好 ——
     避免拖动过程中几十次写磁盘。
   - 读数与说明文案随值变化：100% 时提示「当前为标准大小，只想放大文字请用上面的『文字大小』」，
     非 100% 时说明放大后**一屏能放的内容会变少、必要时窗口需拉大**（不隐瞒副作用）。
2. **与既有「文字大小」正交**，不是同一件事
   - 既有的 `textScale`（90%~120%）只改 8 条手写 `font-size` 规则 —— 是**排版级**的字号档位。
   - 新的 `uiScale` 走 CSS `zoom`，是**布局级**的整体缩放，两者互不干扰，可以叠加使用。
   - 文案里明确把两条路的适用场景分开写，免得用户以为功能重复。
3. **「恢复界面默认」会一并复位缩放**，且复位后**强制重渲染卡片** ——
   不重渲染的话滑块 DOM 还停在旧位置，看起来像「按了没反应」。

实现要点（都写在 `src/uiScale.js` 头部注释里，这里是结论）：

- **缩放本体是 `documentElement.style.zoom`**，不是 `transform: scale()`。
  选 `zoom` 是因为它**参与布局** —— 元素按缩放后的尺寸占位；`transform` 只改绘制不改布局，
  会留下一堆叠在一起的空洞。
- **两个必须记住的 `zoom` 陷阱**（本批实测踩到）：
  1. **`position: fixed` 的包含块变成被缩放元素**。`bottom: 22px` 的含义变成
     「距缩放容器底边 22px」而不是「距屏幕底边」；120% 时容器已超出视口 20%，
     `bottom` 锚定的浮层直接跑到屏幕外。同理 `100vw` / `100vh` **不会**被缩放系数自动除回去，
     乘出来比屏幕更大。
  2. 解法：JS 注入 `--ui-vw` / `--ui-vh`（= 视口长度 ÷ 缩放系数，即「缩放前的长度」），
     所有 `fixed` 浮层改写成 `calc(var(--ui-vh, 100dvh) - 22px)` 这类形式。
     本批改了 13 处（`.drawer` / `#toasts` / `.toast` / `.cap-modal` / `.cmd-palette` / `.quick-cap` /
     `.ai-rule-editor` / `.update-toast` / `.settings-modal` / `.main` / `.time-viewmenu` /
     `.settings-catalog` / `.settings-content`）。`inset: 0` 的四处遮罩层不用改（0 在两个坐标系里同值）。
- **测试里加了一条反向源码守卫**：`fixed` 浮层的声明里出现裸 `100vw` / `100vh` / `100dvh`
  即失败 —— 这条守卫在写的时候就抓出了 4 处我手改漏掉的声明。

#### ⚠️ 一条被实测推翻的旧结论（别再照抄）

开发这个功能时，我原先的假设是：**把视口断点从 `px` 改成 `em`，断点就会跟着缩放走**，
于是「150% 时自动切成手机布局」这种效果就白拿了。**这个假设是错的，实测推翻了它。**

三条 `matchMedia` 决定性实测（无头 Chrome，视口 1280px，`zoom = 1.5`，
`getComputedStyle(document.documentElement).fontSize` 实测为 **24px**）：

| 查询 | 实测结果 | 若 `em ≡ 24px` 应为 | 若 `em ≡ 16px` 应为 |
|---|---|---|---|
| `(max-width: 40em)` | `false` | true（960 < 1264） | true（640 < 1264） |
| `(max-width: 56.25em)` | **`false`** | **true**（1350 > 1264） | false（900 < 1264） |
| `(max-width: 65em)` | **`true`** | **false**（1560 > 1264） | true（1040 < 1264） |

**只有「`em` 恒等于 16px」这一种解释能同时对上三行。** 也就是说：

> **`em` 媒体查询按浏览器初始字号（16px）求值，既不认 `zoom`，也不认 `html { font-size }`。**

推论：**`px` 断点与 `em` 断点在缩放下的行为完全相同**，改单位没有任何收益。
（这也是为什么 `html { font-size: calc(16px * var(--ui-scale,1)) }` 那把「字号标尺」被删掉了 ——
它不影响任何媒体查询，纯属摆设。）

**已按此结论回退全部 33 处 `em` 断点回 `px`**，并加了两条守卫防回归：
`test-ui-scale.mjs` 的 **3d 反向守卫**（媒体查询里出现 `em` 断点即失败，附实测原因）与
**3e 断点精确计数表**（各宽度断点出现次数逐一固定，`900px` 计数 4 等）。变异测试 5/5 全被拦下。

**已知边界（本版刻意不做）**：缩放**不改变布局断点** —— 布局仍由真实窗口宽度决定。
想做到「缩放后自动切手机布局」，唯一可行路径是改用**容器查询**（`@container` 确实会随 `zoom`
走，实测在 `zoom=1.5` 时匹配、`1.0`/`0.8` 时不匹配）。但 `@container` 要求被匹配元素是
容器的**后代**，而本项目的断点大量指向 `.topbar` / `.drawer` / `.cmd-palette` / `.quick-cap` /
`.settings-modal` / `#toasts` 这些 **`#app` 的兄弟节点**，从 `#app` 容器出发永远匹配不到 ——
要做就得搬 DOM 挂载点，风险大、收益有限。**本版按用户决策只做等比缩放，容器查询留作独立版本评估。**

### 批次八 · 修复任务详情抽屉里多出一行 `null`（用户截图报障）

**现象**：四象限里点开任意任务，右侧抽屉在「任务名称」与「标签」之间多出一行**裸 `null` 文本**
（无标签、无控件，就是四个字母），桌面与手机端都有。

**根因**：`src/views/drawer.js` 里 `body.append(...)` 用的是**原生 `Element.append()`**，
不是项目自研的 `el()` 助手。原生 `append()` 会把非 Node 参数**字符串化**后插入 ——
`append(null)` 会真的写出一个文本节点 `"null"`。而实参列表里恰好有这样一条：

```js
t.sourcePlugin ? el("div", { class: "kv" }, …) : null,
```

这是「插件联动提醒」那一行（只有当任务由插件创建时才显示）。`t.sourcePlugin` 为假时取 `: null` 分支，
于是把 `null` 交给了原生 `append`。**手动创建的任务占绝大多数**（只有插件通过 `tide.tasks.create`
建的任务才带 `sourcePlugin`），所以这个 bug 是**常态触发**，不是边角情况。

对照：`el()` 自己在 `src/ui.js` 里是有容错的 ——
`for (const c of children.flat()) { if (c === null || c === undefined) continue; … }`。
问题就在于这段容错**只管 `el()` 自己的子节点**，对直接调原生 `append()` 的地方毫无作用。

**修复**：把这一串实参先收进数组、`filter(Boolean)` 之后再展开：

```js
body.append(
  ...[
    el("div", { class: "kv" }, el("span", {}, "任务名称"), titleInput),
    t.sourcePlugin ? el("div", …) : null,   // ← 现在会被过滤掉
    el("div", { class: "kv" }, el("span", {}, "标签"), tagsInput),
    …
  ].filter(Boolean),
);
```

顺手在 `src/views/drawer.js` 里把这条陷阱写成了注释（原生 `append` 会字符串化假值，
不能照抄 `el()` 的写法），并在 `scripts/test-plugin-task-source.mjs` 加了**回归守卫**。

**影响面排查**：写了个 AST 式扫描器，把全仓库 `src/` 下所有 `.append( / .prepend( /
.replaceChildren(` 调用的实参列表扫了一遍，找「三元以 `: null` 收尾且后随逗号」与「裸 null 实参」。
共命中 4 处，逐一核对后确认**只有 `drawer.js` 这一处是真 bug**：
`views/inbox.js:16-20`（两个按钮三元）与 `views/timeViews.js:313/331`（`c.position ? … : null`）
的三元都**嵌套在 `el(...)` 的实参里**，会被 `el()` 的过滤器接住，安全。

**回归守卫**（`scripts/test-plugin-task-source.mjs` 段 5）：
断言 `body.append(` 的**唯一实参**必须以 `...[` 开头、以 `.filter(Boolean)` 收尾 ——
即「先过滤再展开」，从结构上堵死「把假值直接交给原生 append」这条路。
**变异测试 3/3 被杀死**（去掉 `filter(Boolean)` / 去掉展开符 `...` / 把 `filter(Boolean)` 换成恒真函数），
且每次变异后回读源文件确认已还原。

**真浏览器验证**（无头 Chrome + iframe 强制真视口，真 CSS 真数据）：
造两条任务分别覆盖两条分支 —— 普通任务（无 `sourcePlugin`）与插件任务（带 `sourcePlugin`）。
修复前后各扫一遍抽屉 DOM 里的裸 `null` 文本节点：

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 普通任务（无来源插件） | **1 个 `null` 文本节点**，位于 `.dbody` 下、任务名称与标签之间 | **0 个**；13 行，顺序为 任务名称 → 标签 |
| 插件任务（带来源插件） | 0 个 | **0 个**；14 行，多出的「来源插件」行图标与名称正常 |

截图 `output/preview/drawer-fix-{1280,390}.png`（明色、桌面与手机两档）目检确认：
`null` 行消失，「来源插件」行在有来源时仍正常。

### 批次五 · 新插件「轮换值日」（`dorm-duty`）

把「按成员顺序轮换」的公共事务（宿舍值日 / 打水 / 倒垃圾…）集中管理，到点提醒当班的人。
第 13 个内置插件，排在考试日历之后、「插件使用说明」之前（`order: 13`）。

1. **用「轮次」建模，而不是「每天算一个人」**
   - 起始日按周期切段，一段一人。这样「每周轮换」的整周都显示同一个人，提醒也只在每段第一天触发一次 ——
     否则会天天催人（这是最容易写错的地方，测试与变异测试都专门守着它）。
   - 周期支持每天 / 每 3 天 / 每周 / 每两周与自定义 N 天（1–365）。
2. **成员管理**：增删、改名、上下调整轮换顺序（顺序即轮换顺序，第一个人先值日）；
   误删的成员进「已移除」名单可一键恢复，恢复时加回末尾，不改动已经过去的轮次。
3. **临时换人按轮次起始日记**：一次换人管一整轮（周期 = 1 时就是当天），撤销即回到原排班；
   被换的人若已被移出名单，自动退回正常轮换而不是显示空白。
4. **提醒**：可设时刻与提示音（复用应用设置里的音效目录），只在每轮第一天提醒一次；
   当天没打开应用、之后才打开时会补提醒一次。提醒前先落盘 `lastNotified` 再弹通知 ——
   万一还有旧实例同时 tick，也只有一个能抢到写入。
5. **加入今日任务**：一键把本轮值日做成一条今天的任务（`quad: 2` / `estMin: 15` / 标签 = 事项名），
   同日同名的未完成任务视为重复，不重复添加。
6. **配色一律走主题变量**，深色模式自动跟随；无硬编码色值（只有错误文案用固定红）。

三个必须记住的实现约束（写在这里免得下次踩）：

- **停用再启用会重新执行整个模块**，旧实例的 `setInterval` 还活着 → 用 storage 里的「代号」（`gen`）
  让旧实例发现自己被顶掉后 `clearInterval` 退出，否则会双份提醒。
- **停用（不重启用）只摘注册**，`interval` 仍在 → `tick` 里查侧栏里本插件入口还在不在，不在就自终止。
  但启动早期导航还没渲染（没有 `nav.nav`）时**不算停用**，避免误自杀。
- **提醒时刻必须真校验时/分范围**，不能只校验 `/^\d{2}:\d{2}$/`：
  `"25:99"` 能过格式校验，但换算成 1599 分钟 > 一天最大值 1439，会让「还没到点」永远成立 ——
  提醒被**静默关掉**（不报错、不提示，最难查的一类失效）。这是本批开发中实测到并修掉的真实 bug，
  回归测试用「存量配置里存着 25:99 时仍须照常提醒」守着。

顺带修的两处版式问题（真浏览器实测发现，DOM 垫片看不出来）：

- **窄屏轮次标签被撑成整行横幅**：媒体查询里 `.dd-d{grid-column:1/-1}` 会打乱自动排布，
  把 `.dd-tag` 挤到下一行的第 1 列，`1fr` 列让它拉满整行。改为显式 `grid-row/column` 定位。
- **桌面端日期被挤成两行**：原 `grid-template-columns:150px 1fr auto` 让日期落在 `1fr` 列，
  「10月12日 — 10月18日 · 周一」这种最长串在 1280 宽下折行。改为 `96px auto 1fr`
  并把弹性让给右侧标签列（标签 `justify-self:end`）。

平台支持：Windows / Android / 微信小程序**三端都做了**。

- 桌面与 Android 共用前端实现（`public/plugins/dorm-duty/main.js`）。
- 小程序端是独立实现：纯逻辑在 `miniprogram/core/pluginRuntime.js`（`dd*` 一组纯函数 + `dormDutySummary`），
  页面在 `miniprogram/pages/plugin/index.js` 的 `loadDormDuty` 与 `onDd*` 一组处理器。
  **存储键与桌面端逐字一致**，所以备份导出后跨端恢复不丢配置；`config` 里桌面端才用的 `sound`
  在小程序侧原样保留，不会被小程序保存一次就抹掉（测试守着这条）。
  （批次六把存储结构改成了多套轮换，具体键见下。）
- 小程序**不能常驻后台**，也没有宿主定时回调，因此到点提醒只在打开插件页时补一次
  （每轮第一天 + 已过设定时刻 + 当天没提醒过），页面上如实写明；要系统通知请用桌面 / Android 端。

### 批次六 · 轮换值日支持多套轮换（宿舍 / 公区各一套）

原先一个插件只有一套轮换，宿舍值日和公区卫生只能二选一。本批改成**一个插件里装多套互相独立的轮换**：
每套有自己的成员、周期、起始日、临时换人记录与提醒时刻（含各自的「今天已提醒过」去重标记），互不影响。
插件显示名随之从「宿舍值日」改为「轮换值日」（id `dorm-duty` 不变，插件版本 1.0.0 → 1.1.0）。

1. **存储结构：单例 → 列表**
   - 新增 `groups`（数组）与 `activeId`（当前显示哪一套）；每套组内的键与原先一致
     （`members` / `overrides` / `removed` / `lastNotified` / `startDate` / `periodDays` / `remindTime` /
     `remindEnabled` / `sound` / `name` / `id`）。
   - **旧数据自动迁移**：`groups` 不存在时读旧键（`members` / `config` / `overrides` / `removed` /
     `lastNotified`）合成一套轮换，字段一个不丢（含 `config.sound` 与「已提醒」标记）。
     `groups` 一旦存在就**不再看旧键** —— 否则旧客户端写的快照会把新版数据盖回去。
   - **迁移与兜底建组立刻落盘**：不写的话「已迁移」与「未迁移」在存储上分不出来，
     每次进页面都会重建一个**随机 id** 的默认组，用户刚设好的东西下次就没了。
     桌面端与小程序端都守这条（变异测试确认：去掉落盘，两次进页面拿到的组 id 不一致）。
2. **组切换条**：顶部列出全部轮换，每枚标签直接显示**该套当前的当班人**（一眼看出谁在轮），
   当前那枚高亮。切换只重画插件内部，**侧栏导航不重建**（真浏览器实测：切换期间导航 DOM 变更 0 次）。
3. **新建 / 改名 / 删除**：最多 12 套（防病态数据把界面撑爆）；新建的套**不继承**上一套的成员，
   建完自动切过去；删除当前套时当前指针落到邻居，**最后一套不许删**（删光界面就没有可编辑的对象了）；
   删除要二次确认，误点不能直接抹掉排班。
4. **提醒按组遍历**：多套同时到点就各弹一次，去重标记**按组独立**（A 组提醒过不影响 B 组）。
5. **同名成员不串台**：每组各自一份成员名单与换人记录，A 组换人不改 B 组排班。

两处归一化上的防守（都是「脏数据不能把页面画崩」）：

- **重复 id 必须剔掉**，否则「切换轮换」会指错对象；组数超限要夹住。
- **指向已移除成员的临时换人「不算换人」**：旧版本可能留下这种存量数据，若不判断，
  界面会显示「已换人 · 原 X」而当班的**就是** X。这类 override 在归一化时也会被顺手清掉。

顺手修掉一个只有靠眼睛才发现的显示 bug：轮次行的日期写成「9月18日（周五）· 周五」——
`fmt()` 已经带了周几，外层又补了一次。现在单日轮次是「9月18日（周五）」、多日轮次是
「9月14日 → 9月20日 · 周五起」，两端文案一致，并有断言守着「周X 只能出现一次」。

还修了一处**控件位置与语义错位**：「本轮换人」的下拉框原先被塞在「下次换人」卡片里，
但它改的是**当前这一轮**（`overrideHit` 用 `s.cycle`）—— 放在「明天换人 / 9月18日 轮到 老陈」
下面，会让人以为换的是下一轮。现在挪进本轮卡片（小程序端本来就在本轮卡片，桌面端对齐过来），
并有断言 + 真浏览器判据守着「`data-swap` 必须在 hero 卡片里、不能在下次换人卡片里」。

平台支持与批次五相同（三端都做了），小程序端的存储键与桌面端仍然逐字一致，
所以批次五之后导出的单套备份在升级后能被自动迁移，跨端恢复继续可用。

## 数据迁移

**批次六有一次性自动迁移，无需用户操作**：旧版单套轮换的数据（`members` / `config` / `overrides` /
`removed` / `lastNotified`）在首次打开插件时自动合成一套轮换写进 `groups`，字段一个不丢
（含 `config.sound` 与「已提醒」标记）。迁移结果**立刻落盘**，且 `groups` 一旦存在就不再读旧键 ——
否则旧客户端写的快照会把新版数据盖回去。旧键**不删除**（作为回退余地），但不再被读取。

其余批次不改数据结构：`closeToTray` 缺省即「直接退出」，`checkedAt` 是会话级内存态，
`lastCheckAt` 是既有字段，批次四只改 UI 与选择集（内存态，不落盘）。
批次七在偏好对象里**新增一个字段 `uiScale`**（缺省 `100`），存量用户首次读到的偏好里没有它 ——
`normalizeUiPreferences()` 会补成 100（即「什么都不动」，与升级前视觉完全一致），
所以**老用户升级后界面不会突然变大或变小**。归一化有类型闸门：非数字/非数字字符串
（`true`、对象、数组）一律回退 100，空串与 `0` 也当「没设置过」，`±Infinity` 夹到两端，
先夹取再对齐步进（反过来 `Infinity / 5 * 5` 会先算出 `NaN`）。
**批次八纯 UI 修复，不动任何数据结构** —— 已有任务（无论有没有 `sourcePlugin`）升级后直接正常，
无需迁移。
插件对缺字段 / 坏字段一律退回可用默认值（不会因为配置损坏白屏）。

三端存储键**逐字一致**（批次六起是 `groups` + `activeId`，组内的键与旧版同名），
所以「桌面填好成员 → 导出备份 → 小程序导入」能直接接着用；反向同理。
组里只有桌面端会用的 `sound`（提示音）在小程序侧原样保留、不展示也不改写。
