# v0.67.0 · 局域网直连：同一个 Wi-Fi 下，手机直接从电脑拉数据，不经过网盘

## 改了什么

「可选同步」卡在 v0.62.0 有了网盘三步引导，但网盘这条路有两个硬前提：**要有一个网盘账号**、
**要能上网**。本版补上第二条路 —— 手机和电脑在同一个 Wi-Fi 时，跳过网盘直接拿。

### ① 这条路径是**单向**的：只能「手机拉电脑」

电脑端的局域网服务对数据**只读**（`src-tauri/src/lan.rs` 顶部注释 + 测试里的反向断言）。
唯一的写入口一直是 `/api/command` 那两条动作（勾选任务 / 快速添加），本版**没有新增任何数据写入口**。

为什么不开「手机 → 电脑」的推送：那是唯一一条能隔着网线覆盖整台设备数据的路径，
而这个场景里电脑往往是唯一有完整备份的那一端。同网段任何拿到配对码的人都能抹掉电脑数据，
风险不对称（省一次点击 vs 丢整台电脑的数据）。

为什么手机端不建服务：手机在 Wi-Fi 客户端模式下常被 AP 隔离挡住入站连接，切后台还会被系统冻结 ——
做成服务端会得到一个「时好时坏」的功能，比没有更糟。

### ② 电脑端加只读端点 `/api/info`（`lan.rs`）

拉之前先让人看清电脑上是什么货：

```json
{ "ok": true, "appVersion": "0.67.0", "savedAtEpoch": 1760000000,
  "dataOk": true, "tasks": 128, "blocks": 43 }
```

`dataOk` 是 `data.json` 能不能解析 —— 读不出来时如实说，**别让手机拉到一份空数据还以为成功**。

### ③ 客户端 `src/lanSync.js`（新）

`parseLanTarget` 一个框吃下所有粘法（小白只会复制粘贴，不会拆字段）：

| 粘进来的东西 | 解析结果 |
|---|---|
| `http://192.168.1.5:27123/m?token=ab12` （电脑「复制链接」的整条） | base + token 全自动 |
| `192.168.1.5` | 补默认端口 27123 |
| `192.168.1.5:27123 ab12cd34` | 地址 + 空格 + 配对码 |
| `10.0.0.9:8080/` | 吃掉结尾斜杠 |
| `27123`（只填了端口） | 直接说「地址要写成 192.168.1.5 这种形式」 |

错误也一律翻成人话：403 → 「配对码不对，去电脑上重新复制链接」；
404 → 「连上了但那台电脑没在跑本程序，或者端口写错了」。

### ④ 引导卡新增一段「不用网盘：从电脑直接拉」（`views/settings/sync.js`）

- 两个按钮：**连接看看电脑上有什么** → 回显条数与落盘时间；**拉回本机** 在前者成功之前一直是 `disabled`，
  连接失败会重新锁回去。
- 「电脑上要怎么准备？」就地展开 4 步（开程序 → 启动联动服务 → 复制链接发到手机 → 粘进来）。
- 桌面端多一个按钮直接跳到「局域网联动」那节去启动服务。
- **配对码不落盘**，只记地址。存进 `settings` 就等于存进 `data.json`，而 `data.json` 会被 WebDAV
  原样传到网盘上 —— 那等于把电脑的钥匙上传云。

### ⑤ 顺手统一了两条拉取路径的安全动作

覆盖本机数据之前**一律先自动存一个恢复点**（设置 → 数据中心 → 自动备份），拉错了能退回去：

| 路径 | v0.62.0 | 本版 |
|---|---|---|
| 从网盘拉回本地 | 只在确认框里**建议**「先导出备份」 | 自动 `createAutoBackup("从网盘拉回前")` |
| 从电脑局域网拉回 | —— | 自动 `createAutoBackup("局域网拉回前")` |

同时**去掉了拉取成功后的整页重渲染**：原来 `rerender()` 会把刚打出来的「已拉回本机 · N 条任务」
那行提示当场擦掉，用户完全不知道有没有成功（无头 Chrome 点出来的，不是想出来的）。
数据本身由 store 订阅者刷新，不需要重建设置页。

### ⑥ 一个要说破的既有语义（不是本版引入的）

拉回来的是对方那份**整份状态**，`settings` 也在其中 —— 所以从电脑拉一次，
手机上的「同步设置」（网盘根地址、文件夹、账号）会被电脑那份换掉。
这是快照替换模型一直以来的行为，本版做的两件事：

- 卡片上写明白，并指出可以用恢复点退回；
- 确认框里报出条数与「会覆盖本机」，不再让人按了才知道。

**配对码不在其中**：它从来不进 `settings`，只进 Rust 侧密钥库都不进（局域网这条干脆只存内存），
否则它会跟着 `data.json` 被 WebDAV 传到网盘上。

## 影响哪端

- **Android（APK）**：这是手机端目前唯一不需要网盘账号就能用的迁移路径。
- **Windows（exe）**：同一张卡，桌面端多一个「本机就是电脑 · 去启动服务」直接跳到局域网联动那节。
- **两端都要求**：`lan.rs` 的 `/api/info` 未加平台门控，与 `/api/state` 同一条路径。
- **微信小程序**：不涉及。

## 有没有数据迁移

`settings.sync` 新增 `lan: { host }`（只存地址）。老字段一律不动，无迁移。
