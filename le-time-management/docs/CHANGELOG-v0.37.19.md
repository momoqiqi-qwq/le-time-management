**多选型勾选框刻意没动** —— 插件批量选择、AI 自动任务的「每周几」是**多选**，换成滑块是语义错误。

### 做法

新增 `src/switchControl.js` 作为唯一出口：

```js
toggleSwitch({ checked, onChange, ariaLabel })
```

语义仍是**原生 `<input type="checkbox">`**（不是 div 扮的开关）：`checked`、`change` 事件、
键盘空格、屏幕阅读器、表单语义全部保留，调用方照样读 `.checked`。外观钩子固定为
`class="switch"` —— 与插件中心原有的 `<button class="switch">`（靠 `.on` 类名）**共用同一套样式**，
所以插件中心的开关外观也一起变了，行为不变。

尺寸收敛到 `--switch-w / --switch-h / --switch-pad` 三个变量，滑块头的开关位移改用
`transform: translateX(...)`，不再手写 `left` 距离；`prefers-reduced-motion` 下关掉过渡。

配色配方（走令牌，不写死颜色）：

| 部位 | 取值 | 理由 |
|---|---|---|
| 关闭态轨道 | `color-mix(in srgb, var(--ink) 55%, var(--panel))` | `--ink` 随模式翻转 → 两种模式下都是**中性中灰**，既能和面板拉开、又不会亮得像开着 |
| 打开态轨道 | `var(--deep)` | 强调色，一眼分清开/关 |
| 滑块头 | `var(--panel)` | 浅色下白、深色下深，两边都压得住 |

旧版写死的 `#D8D2C6` 轨道 + `#fff` 滑块头被断言禁止回来（深色下白点几乎看不见）。

### 🔴 深色下开关会「整块消失」——实机探针才抓到的坑

`styles.css` 里有一条深色兜底规则，专门压掉各视图里写死的 `background:#fff` 输入框：

```css
/* 旧写法：连 .switch 一起连坐 */
:root[data-theme-mode="dark"] input { background: var(--panel) !important; }
```

滑块开关是 `<input>`，于是**轨道被 `!important` 整体刷成 `var(--panel)`**，而滑块头本来就是
`var(--panel)` —— **开/关两个状态、轨道和滑块头全是同一块颜色**，深色下既看不出开关在哪、
更看不出开着还是关着。改成 `input:not(.switch)`。

这一条纯静态断言发现不了，而且第一次探针读到的「轨道色 == 面板色」一眼看过去像是
**过渡动画在读值途中被量到了**，差点当噪声放过。做了三步才定性：

1. **隔离页复现**（只挂 `styles.css` + `theme-derived.css`，注入 `*{transition:none}` 关掉过渡）
   → 深色下轨道是中性中灰 `rgb(145,142,137)`，与面板色明显不同，说明实测那次读到的是过渡插值；
2. **变异证伪**：生成一份「修复前」的 CSS 副本（`input:not(.switch)` 还原成 `input`），
   15 套主题 × 深色**全部塌成同一种颜色** —— 轨道 = 开态轨道 = 滑块头 = `--panel`；
   修复后 30 组全部互不相同。**证明这条修复确实必需，不是「顺手加的保护」。**
