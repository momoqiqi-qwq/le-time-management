# v0.60.1 · 竞赛消息雷达：残留筛选不再把列表滤成空白

## 症状（只出现在 APK）

手机端打开「竞赛消息」，状态行是 `已更新 14:20 · 拉取 40 条 · 显示 0 条`，
下面一句「没有符合过滤条件的消息」。看着像抓取失败，实际**网络与接口都是好的**：
40 条已经拿到手，是被**上次点出来的筛选条件**全滤掉了。

最典型的是「月份」那一排 chip：它存的是绝对月份（如 `2026-05`）。跨过一个月之后本次抓取里
就没有这个月了，于是永远命中 0 条 —— 而月份 chip 是按当前列表里真实存在的月份生成的，
残留的那个月根本不在其中，**一个 chip 都不会高亮**，界面上完全看不出还在过滤。

- 插件存储随 `data.json` 走，手机与电脑各存各的（没开同步时互不影响），
  所以同一份代码两端表现不一致：Windows 正常、APK 空白。
- 「只看未读」「类型 = 其他」这类残留勾选是同一个坑的另外几种写法。

## 改了什么

`public/plugins/gx-news/main.js`（0.3.0 → 0.3.1）：

### ① 失效月份自动回「全部」

抓到第 1 页后，把 `filter.month` 与本次真实存在的月份对一次，命不中就静默回 `all` 并落盘。
命得中的月份原样保留，不抹用户的选择。

### ② 持久化筛选值读回来先归一类型

新增 `sanitizeFilter()`：关键词强制成字符串、旧版原始类型码（`202` / `203`）迁到 `n202` / `n203`、
非法类型回 `all`、非 `YYYY-MM`（且非 `unknown`）的月份作废回 `all`、两个开关转布尔。
原来只在内存里做的类型迁移现在也收进了这一个函数。

### ③ 空态把「正在生效的筛选」说出来

`已抓取 40 条，被筛选全部滤掉了 / 生效中：月份「2026年5月」、只看未读`，
并在下方给一颗「✕ 清除全部筛选」按钮（一次清掉关键词 / 类型 / 月份 / 只看未读，保留封面图与自动刷新）。
空白关键词不算生效筛选，不会误报。

## 影响范围

- 只改 `gx-news` 一个插件的前端逻辑，**没有数据迁移**：脏值一律读时归一，不回写覆盖。
- Windows / Android 同源代码同一行为；小程序端是另一套原生适配页（`miniprogram/pages/plugin/index.js`），本版未动。
- 版本号 0.60.0 → 0.60.1，插件 0.3.0 → 0.3.1。插件版本进了入口 URL 的 `?v=`，
  **APK 覆盖安装后 WebView 才会弃掉旧的 `main.js` 缓存**，这是这次修复能在手机上生效的前提。

## 验证

新增 `scripts/test-gx-news.mjs`（真跑插件源码 + `tide` 桩 + 最小 DOM 桩，4 组断言）：
失效月份自愈、命得中的月份保留、脏值归一后空态文案正确、点清除后消息回来。
拿旧版 `main.js` 跑同一份测试会在第 ① 组断言失败，测试不是空转。
