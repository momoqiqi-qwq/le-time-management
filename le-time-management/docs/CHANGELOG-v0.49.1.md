# v0.49.1 变更说明

> 发布日期：2026-09-17（未提交 / 未打 tag 状态下写入本文件，随本版本一并提交）
> 版本类型：patch（交互修正）

## Android / 窄屏：设置页不再「一进来就展开界面与交互」

### 现象

手机上（APK）打开设置页，第一个分区「界面与交互」默认就是摊开的，
内容一直铺到屏幕底部 —— 11 个分类里只看得见它一个，
「主题 / 任务提醒 / 数据中心 / 插件管理……」这些全被挤到屏幕外，
看起来像「设置里只有界面与交互这一项」。

### 根因

窄屏（≤980px）设置页是手风琴结构（`src/views/settings/navigator.js`）。
初始化时有一句兜底：

```js
if (narrow.matches && active) expanded.add(active);
```

它的本意是避免「全都收着、点了设置像打开的是一张目录」，
但代价就是**一进设置页必定展开第一个分类**。而用户要的恰恰是那张目录。

### 修复

| 项 | 内容 |
|---|---|
| 初始不展开 | 去掉初始预展开与断点变化时的预展开；进来就是 11 行分类标题，谁都不展开 |
| 点标题才展开 | 展开 / 收起完全由 `.settings-acc-head` 点击决定（原行为不变） |
| 展开状态写回 `settingsNavState` | 在设置里改任何一项都会整页重渲染；状态若只存在 navigator 局部变量里，刚展开的面板会当场塌掉。现在 `state.expanded` 跨重渲染保留 |
| 每次打开设置页清空 | `renderSettings()` 开头 `settingsNavState.expanded = []` —— 重新进来仍是目录态，不记住上次展开 |
| 外部点名跳转不受影响 | `select(id)`（如更新提示条的「立即更新」）仍会展开目标分区并滚到它，那属于用户明确指定 |

### 影响范围

- **窄屏（手机 / APK，≤980px）**：行为改变。
- **桌面（>980px）**：不受影响 —— 标题行隐藏，仍是「左侧分类 + 右侧单页」，
  一进来照旧显示当前分类内容。
