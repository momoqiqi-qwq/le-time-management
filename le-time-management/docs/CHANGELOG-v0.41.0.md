# Le时间管理 v0.41.0

> 上一版：v0.40.0（小程序插件中心原生适配扩到 8 个：插件说明 / 微信推送 / 竞赛雷达 / 学习通）
>
> 本版改动集中在**网页收集插件（web-collector）的图标获取能力**：
> 把「获取图标」从「和识别标题绑在一起的一次性动作」拆成**可单独触发**的两个入口。

## 本版内容

### 背景

原来网页收集只有一条路能拿到图标 —— 点「自动识别并收藏」，
它一次性抓标题 + favicon + Font Awesome 名，然后整条覆盖写入。
由此有三个实际问题：

1. **想只换图标做不到**：图标抓错了（比如只抓到默认的 `/favicon.ico` 白板），
   只能点「刷新名称/图标」，但那个操作会**连用户手改过的标题一起覆盖掉**。
2. **收藏前看不到图标**：先收藏、再发现图标不对、再删掉重来，多绕一圈。
3. **图标来源不可见**：界面上只显示 `FA: globe` 这类推断名，
   看不到实际抓到的 favicon 地址，出问题时无从判断。

### 改动 1：顶栏新增「自动获取网站图标」按钮（web-collector 1.1.2 → 1.2.0）

- 输入网址后点它，**只抓图标**，不改动任何已收藏条目。
- 结果以**预览条**形式出现在输入区下方：缩略图 + 实际图标地址（可复制排查）
  + 「存为新条目」/「清空」两个后续动作。
- 抓不到时回退到 `<域名>/favicon.ico`，并如实提示。
- 下拉区的说明文案同步补了两句，讲清「获取图标」与「自动识别并收藏」的分工。

### 改动 2：每张卡片新增独立「换图标」按钮

- 与「刷新名称/图标」分开：**换图标只回写 `iconUrl` / `iconName` 两个字段**，
  标题、备注、host 全部原样保留。
- 这下「标题是手改的、但图标想重抓」这种场景不用再牺牲标题。

### 改动 3：图标来源不再隐形

卡片仍显示 `FA: <推断名>`，预览条里补上**真实 favicon 地址**。
排查「为什么图标是白板」时，能直接看出是网站没提供、还是抓到了 404 的默认路径。

### 改动 4：窄屏下图标地址保持一行可读

初版预览条里图标地址用了 `word-break:break-all`，390px 手机宽度下
`https://www.resource.edu.cn/favicon.ico` 被逐字符折成 **4 行竖排**（`http` / `s://www.resourc` /
`e.edu.cn/favico` / `n.ico`），基本读不出来。改为：

- 地址 `white-space:nowrap` + `overflow-x:auto`：保持单行完整，超长时横向滚动。
- 窄屏（≤640px）下 `.wc-preview-text{flex-basis:100%}`：地址独占一行，
  不再被「存为新条目 / 清空」两个按钮挤到只剩十几个字符的可见宽度。

> ⚠️ 别把 `word-break:break-all` 加回来。它看起来"更安全"（不会溢出），
> 实际把 URL 折成无法辨认的竖排。已有回归断言守着这条。

### 改动 5：学校通知插件加 30 秒网络看门狗（school-notice）

用户反馈添加 `https://www.guet.edu.cn/zs/`（桂电招生网）时按钮永远停在「处理中…」。
排查结论：站点本身 1 秒内 200、**无登录表单**、同一份解析代码在无头 Chrome 里
15ms 抓出 45 条公告 —— 卡死发生在应用实例内部（请求桥 invoke 挂死），
而插件的 `busy` 状态**没有任何超时兜底**，一旦某次 `tide.http.fetch` 的 promise
永不 settle，按钮就永远转圈。

- `fetchPage()` 全部网络调用套 `Promise.race` 看门狗（30 秒），
  超时后 UI 必然恢复并提示「请求超过 30 秒未响应，已中断」。
- `refresh()` 的 `busy = false; paint()` 挪进 `finally`，异常路径也能复位。
- `addSite()` 的首次读取改走 `fetchPage()`，与其它路径共享看门狗。

> 说明：插件本来就不会「自动登录」——只有当页面里检测到密码框才显示登录配置区。
> 桂电招生页没有表单，整个流程与登录无关。

### 改动 6：学习通插件刷新策略改为界面二选一（chaoxing-notify 2.7.0 → 2.9.0）

用户反馈：**每次打开学习通插件都停在「刷新中…」**。原因是 `render()` 在自动登录成功后
无条件 `await refreshAll()`——每次进入视图都拉收件箱 + 课程列表 + 作业状态探测。
随后用户点单：把「节流刷新」和「自动刷新」都做成**界面按钮**，可自由选择，默认自动刷新，
**鼠标悬停按钮显示使用它的原因**。

- 头部按钮区新增一组二选一切关（`自动刷新 | 节流刷新`，拼接式分段按钮，当前档高亮），
  选择持久化到 storage，跨重启保留。**默认「自动刷新」**（保持原有每次打开都拉最新的行为）。
- 两个按钮都有 `title` 悬停提示（同时写进 `aria-label`/`aria-pressed` 无障碍属性）：
  - 自动刷新：每次打开都拉取最新通知、课程和作业状态，数据最及时；代价是每次进入都会向超星发几条请求。
  - 节流刷新：10 分钟内再次打开直接用本地缓存、不发请求，超过 10 分钟才自动刷新；
    省流量、降低对超星的请求频率，数据最多滞后 10 分钟（可随时点「快速刷新」立即更新）。
- 节流档实现：持久化 `lastSyncAt`（毫秒时间戳，刷新/完整同步成功时写入），
  `render()` 打开时距上次同步不足 10 分钟（`AUTO_REFRESH_THROTTLE_MS`）直接用缓存。
- 「快速刷新」「完整同步」按钮不受任何档位影响，随时手动可用。
- `test-chaoxing.mjs` 守卫断言（默认档必须是 auto / render 按策略判断 / lastSyncAt 记录 /
  两档都有 why 文案并渲染进 title / 切换必须持久化），防止将来退化。

### 改动 8：微信推送「服务端验证错误」排障能力（wechat-push 1.4.0 → 1.5.0）

用户反馈：15:05 起「✗ 服务端验证错误」。实测数据还原：15:04 连发 3 条相同的
「Le时间管理测试推送」成功，15:05 起再发全部失败——正中 **PushPlus 官方频次规则**：
**相同内容 1 小时限 3 条、每分钟限 5 次**，超限返回 999（官方返回码表：999=服务端验证错误）。
Token、配置、请求格式都没问题，等 1 小时自动恢复。

- 错误信息带上**官方返回码**：`PushPlus[999]服务端验证错误`，方便对官方返回码表排查
  （903=token 不正确、905=未实名认证、900=当日超限）。
- 失败日志带上**推送标题**：`✗ 推送「Le时间管理测试推送」：…`，能对号入座。
- 识别 999 时日志附**自助提示**：相同内容 1 小时限 3 条、每分钟限 5 条，稍等或改内容即可。
- **测试推送标题带时间戳**（`Le时间管理测试推送 15:07`），天然避开相同内容限制；
  并加 1 分钟防连点（每分钟限 5 次）。

## 实现要点（给后续维护）

- 新增 `fetchIcon(url)` 只回 `{ iconUrl, iconName }`，与整体识别的 `inspect(url)` 分开，
  避免「换图标」误伤标题。
- ⚠️ **顶栏按钮与卡片按钮用了不同的 data 标记**（`data-probe-icon` vs `data-fetch-icon`）：
  事件委托里顶栏分支在 `closest("[data-id]")` 之前，若两者同名，
  卡片的「换图标」会被顶栏分支抢先命中、永远拿不到条目 id。
- 顶栏网格由两列改为 `minmax(0,1fr) auto auto` 以容纳第三个按钮；
  窄屏（≤640px）仍回落为单列，预览条内的按钮保持 `width:auto` 不被拉满。
- ⚠️ **长 URL 不要用 `word-break:break-all`**。它会把地址折成竖排；
  用 `nowrap + overflow-x:auto`，并在窄屏给文本 `flex-basis:100%` 让它独占一行。

## 改动 11 · 微信推送 1.8.0：插件消息攒批合并，兼容 PushPlus 频次限制

**问题**：1.7.0 里插件消息是「每条 notice:new 广播立即推一批（≤10 条）」，学习通短时间多次抓到新通知时会连发多条，逼近 PushPlus「相同内容 1 小时限 3 条、每分钟限 5 次」的拦截线（超限返回 999）。

**方案**：

- 改为**攒批窗口（节流式，2 分钟）**：首条消息入队后开窗，窗口内新消息只进队列、不重置窗口；到点把队列里**全部**待发消息合并成一条推送（标题 `🔔 插件新消息 N 条（HH:MM）`）。请求频率从「每个广播一次」降到「最多 2 分钟一次」。
- 正文按 `PLUGIN_CONTENT_LIMIT = 18000` 字截断（PushPlus 免费版内容上限 20000 字，留余量）。
- 队列上限 40 → 60（`PLUGIN_QUEUE_CAP`）；推送失败整批留在队列，下一分钟的 tick 重试（攒批窗口倒计时中不提前发送）。
- 多选面板新增**待推送实时计数**（`data-ms-queue`）：「待推送：N 条 · 攒批中，最多 2 分钟后合并发送」，发完自动隐藏。

**三端影响**：Windows / Android 生效（同一份 main.js + manifest 1.8.0，sync-plugins 已同步三端目录与图标）；小程序原生适配页不含插件消息队列逻辑。

## 改动 13 · 中国节假日 0.3.0：「查某一天」改自定义大日历，日历内显示节假日

**问题**：原来用原生 `<input type="date">`，弹层小、没法在日历里标节假日、展开收起是系统硬动画。

**改动**（`public/plugins/cn-holiday/main.js`）：

- 移除原生 date input，改为**自绘日历组件**：日期按钮 + 展开面板（‹ › 翻月、周一对齐网格、清除 / 今天快捷键）。

- 插件版本 0.2.1 → 0.3.0，测试断言扩充（无原生 date input 残留、动画类、标记类、今天/清除、降级路径）。
