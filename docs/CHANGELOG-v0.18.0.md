# Le时间管理 v0.18.0

## 改了什么

> 本版包含三项独立功能：学习通 2.4.0「正在批改」标记、警大门户插件 1.3.0「登录一次，全程自动登录」、
> 微信推送插件 1.2.0「官方文档入口与送达语义澄清」。

### 一、学习通 2.4.0：待办作业「正在批改」标记

学习通插件（`chaoxing-notify`）升到 **2.4.0**：待办作业页自动识别**已提交但尚未批改**的作业，
在标题后加「正在批改」标签（琥珀色圆角徽标，悬浮有说明）。

#### 状态是怎么知道的（页面上也写明了）

通知正文里**没有**提交/批改状态，作业状态接口（`getAllWork` 等）实测有权限墙
（返回「没有此页面访问权限 [3004]」），唯一可行信号是**附件里的作业入口页**：

- 通知正文里的附件 iframe `name` 属性是 Base64(URL 编码 JSON)，
  解出 `{examOrWorkId, courseId, clazzId, 作业入口 URL}`（实测 231 条通知里 168 条带这种附件）；
- 后台逐条打开该入口（只读落地页 `<title>`），实测真实账号 12 条样本：
  - title = **「作业作答」** → 还能作答，即**未提交**，不打标；
  - title = **「作答详情 / 查看详情 / 作业详情」** → 已提交后的查看页 → 记为「正在批改」；
- 「是否已批改」没有静态信号（批改结果页是 Vue 异步渲染，各作业形态不一），
  已提交统一标「正在批改」，批改完成以平台通知为准——写在标签悬浮提示里。

#### 刻意做的克制

- **每轮刷新最多探 6 条未知项**、串行逐条进行；状态落插件存储（`workStatus`，一次探测终身有效），
  不重复扫描；请求失败不留记录，下次刷新再试。
- 解析不出附件（纯文本通知、解码失败）的作业直接跳过，不打标、不猜。

### 二、警大门户 1.3.0：登录一次，全程自动登录

警大门户通知插件（`cppu-notify`）升到 **1.3.0**，实现「**登录一次，以后直达消息列表**」：

1. **会话票据跨重启**：登录成功后把门户 Cookie（含 CASTGC 票据，`rememberMe=true`）整体导出，
   加密保存在本机密钥库；下次打开插件先恢复票据走静默续期，有效期内（约 5 天）**零输入直达通知列表**。
2. **密码加密保存**：登录成功后密码存入 Rust 侧 AES-256-GCM 加密密钥库（与 AI 凭据同机制、
   同本机密钥文件），**不进 data.json、不进备份、不进局域网同步**；票据失效时用保存的密码自动重登。
3. **验证码自动识别**：内置纯 JS 数字识别（Otsu 二值化 → 连通域去波浪线 → x 区间分组 →
   16×16 位图匹配「字体模板 + 历史确认样本」），识别失败自动换图重试（最多 6 次）；
   登录成功后当次识别样本回存，识别率随使用提升。登录表单里验证码同样自动识别预填，人工只需核对。

#### 全自动登录三级链路（打开插件时）

```
① 恢复上次会话票据 → 静默续期 → 直达消息列表（绝大多数情况，零输入）
② 票据过期 → 取保存的密码 + 自动识别验证码 → 自动提交，失败换图重试 ≤6 次
③ 全部失败 → 登录表单，账号/密码/验证码全部预填，人工核对点「登 录」
```

密码错误等致命失败会立即跳出自动链路转人工表单，不会反复试错锁定账号。

#### 新增基础设施（供所有插件复用）

- **插件密钥库** `tide.vault.{get,set,del}`：Rust 命令 `plugin_vault_get/set/del`，
  每插件独立命名空间，AES-256-GCM 加密落盘 `plugin-vault.bin`（原子写入、0600 权限）。
  manifest 需声明新权限 `vault`（宿主权限标签：「加密密钥库（保存密码 / 登录票据等敏感凭据）」）。
- **会话 Cookie 导出/恢复** `tide.http.exportCookies/restoreCookies`：Rust 命令
  `http_session_export/restore`。`HttpSessions` 现在持有 `Arc<Jar>` 句柄，可整体导出给定
  URL 下的 Cookie 并在重启后按原 host 属性恢复。

#### 诚实说明

- 验证码识别是**概率性**的（无 tesseract 运行时），单次约七至九成；由「换图重试 ≤6 次」兜底，
  全失败的兜底体验是「全预填、点一下登录」。日常使用以路径①为主，很少走到验证码。
- 若门户更换验证码样式（如改为字母），自动识别会退化为路径③预填表单。

### 三、微信推送 1.2.0：官方文档入口 + 送达语义澄清

经核对 pushplus 官方接口文档，插件既有实现**完全正确**（`POST https://www.pushplus.plus/send`、
`Content-Type: application/json`、参数 `token/title/content/template:"txt"/channel:"wechat"/topic`、
成功判定 `code===200`），无需修改请求逻辑。本次改动：

1. **官方文档入口**：插件界面新增两个链接（经系统浏览器打开，manifest 补声明 `openUrl` 权限）——
   [使用说明 / SDK](https://www.pushplus.plus/doc/guide/sdk.html) 与
   [消息接口文档（参数与返回码）](https://www.pushplus.plus/doc/guide/api.html)。
2. **送达语义澄清**：官方接口为**异步**——`code=200` 只代表 pushplus 已接收请求，公众号实际送达
   以微信侧为准、受平台频控影响。推送日志的 ✓ 从「PushPlus：xxx」改为「PushPlus已提交：xxx」，
   界面底部补充说明与「收不到先发测试消息、再对照官方文档排查」的指引。
3. Token 获取步骤写得更具体：pushplus.plus 微信扫码登录 →「一对一推送」页复制 Token。

## 影响范围

- Windows / Android 共用前端与同一份插件源码，三项功能两端同时生效。
- 微信小程序：三个插件在小程序侧均为 `unavailable` 或无小程序版，只同步应用版本号。
- 学习通项无需重新构建 Rust 侧；警大门户项新增了 Rust 命令（密钥库 + 会话导出/恢复），
  **需要重新构建**（纯增量命令，未动既有逻辑）；微信推送项纯前端，无需 Rust 构建。

## 数据迁移

均无需迁移。插件存储新增 `workStatus`（workId → 状态，首次读取缺省为空对象）；
警大门户未保存过密码的老用户首次仍走手动登录，登录成功一次后自动进入新链路；
微信推送的旧日志记录保持原样展示，新记录使用「已提交」措辞。
关闭「记住密码并自动登录」开关或点「清除保存的密码」即抹掉密钥库中的密码与票据。
