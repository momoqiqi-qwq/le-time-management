# Le时间管理 v0.11.3 代码结构与 UX 优化审查

## 结论

当前项目的核心方向是对的：本地优先、Windows/Android 共用前端、插件清单单一事实源、数据模型跨端兼容、自动化与提醒逐步收敛到统一数据层。v0.11.x 之后最大的体验瓶颈已经从“缺功能”转成“功能越来越多以后，用户如何快速找到、理解和控制功能”。

本次 v0.11.3 因此没有继续堆独立功能，而是先补设置中心的信息架构与界面自由度，并把最膨胀的设置代码拆模块。

## 本次已落地

### 1. 设置页从长列表升级为可搜索设置中心

- 顶部搜索框可直接搜背景、快捷键、WebDAV、提醒等关键词。
- 增加外观、提醒、数据/同步、操作、插件、关于分类。
- 导航区域吸顶，设置项很多时不需要反复滚动回顶部。
- 搜索和分类状态在设置页重渲染时保持。

### 2. 增加界面与交互自由度

新增 `settings.ui`：

- `density`: 舒适 / 紧凑。
- `textScale`: 90%～120%。
- `motion`: 跟随系统 / 完整 / 减少动效。
- `swipeNavigation`: 是否允许触屏左右滑动翻页。
- `showTopStats`: 是否显示顶部任务统计。
- `showViewSubtitle`: 是否显示页面副标题。
- `startupView`: 继续上次页面或固定启动页。

同时提供“舒适 / 高密度 / 低干扰”三套快速预设。

### 3. 设置代码拆分

原 `src/views/settings.js` 约 650+ 行，职责过多。本次拆为：

- `src/views/settings.js`：负责组合各设置区块、数据/同步/快捷键/局域网。
- `src/views/settings/appearance.js`：界面偏好、主题、自定义背景。
- `src/views/settings/plugins.js`：插件导入导出、启停、权限、删除、资源入口。
- `src/views/settings/navigator.js`：设置搜索、分类、过滤。
- `src/uiPreferences.js`：UI 偏好默认值、兼容归一化、DOM 应用和持久化。

主设置文件降到约 330 行，后续增加设置不再需要继续往同一个函数里堆代码。

### 4. 状态健壮性

`store.js` 新增 `normalizeState()`，统一校验顶层 `tasks / blocks / settings / plugins / inbox / automation`，避免异常备份或旧数据把数组/对象字段变成错误类型后直接造成运行时错误。

## 仍值得优化的代码结构

### P0：插件运行环境并不是真正沙箱

当前第三方插件仍使用 `new Function` 执行。即使只把 `tide` 作为参数传入，插件代码仍处于 WebView 全局上下文，理论上能访问 `window / document / globalThis`。现有内置插件本身也依赖 DOM，所以不能简单把这些全局变量禁掉。

下一步应该把“插件 UI”和“插件后台能力”拆开：

- UI 插件运行在隔离 iframe / 独立 WebView。
- 非 UI 逻辑运行在 Worker 或独立执行上下文。
- 宿主通过消息桥暴露最小 API。
- `http` 权限增加域名白名单。
- 插件安装时展示权限摘要和来源风险。

在这之前，产品文案应继续明确“用户插件属于受信任扩展”，不要把当前权限开关描述成安全沙箱。

### P0：缺少正式的数据 schema / migration 层

目前版本号和顶层归一化都有了，但设置字段依然由各模块在使用时 `??=` 补默认值。功能继续增加后，旧版本升级路径会越来越难推理。

建议新增：

- `dataSchemaVersion`。
- `migrations/001.js`, `002.js` 等顺序迁移。
- 启动时只做一次迁移，而不是各页面自行补字段。
- 备份导入先迁移再进入主状态。

### P1：CSS 是“按版本追加覆盖”的结构

`styles.css` 已超过 1400 行，且存在 v0.6 / v0.9 / v0.11 的同选择器重复覆盖。现在还能维护，但继续增长后会出现“改前面的样式却被后面的历史覆盖层吃掉”的问题。

建议拆成：

- `styles/tokens.css`
- `styles/shell.css`
- `styles/components.css`
- `styles/views/settings.css`
- `styles/views/timeblock.css`
- `styles/responsive.css`

并把版本号注释改成职责注释，而不是继续追加新的版本覆盖层。

### P1：设置仍有几个大区块适合继续组件化

`settings.js` 已明显变短，但数据中心、WebDAV、快捷键、局域网仍可继续拆分。推荐下一步按领域拆：

- `settings/data.js`
- `settings/sync.js`
- `settings/shortcuts.js`
- `settings/lan.js`

### P1：同步仍是整包覆盖

WebDAV 当前是“上传本地快照 / 下载覆盖本地”。只要用户在两台设备分别编辑，就存在覆盖风险。

建议下一版至少加入：

- 快照 revision / deviceId / updatedAt。
- 下载前差异预览。
- 任务和时间块按 id + updatedAt 合并。
- 冲突进入统一收件箱，由用户选择保留哪一版。

### P2：跨端设置体验不一致

Windows / Android 现在共享 v0.11.3 的界面偏好；微信小程序会保留这些字段，但暂不应用。

后续如果希望三端“感觉像一个产品”，建议小程序至少同步：

- 紧凑 / 舒适密度。
- 字号档位。
- 首页默认 tab。
- 减少动效。

不建议在小程序照搬桌面背景图等重设置。

## UX 继续优化的地方

### 1. 设置搜索进入命令面板

现在设置页内部可搜索，下一步可以让 `Ctrl/Cmd+K` 搜到“设置 → 自定义背景”“设置 → WebDAV”“设置 → 快捷键”等项目，并直接跳到对应分类/设置卡。

### 2. 快捷键改为“录制式输入”

现在用户需要手输 `Ctrl+Shift+...`。更自然的方式是点“录制快捷键”，然后直接按组合键，实时提示冲突。

### 3. 数据中心加“最近一次保存 / 备份状态”

本地优先产品很需要安全感。建议顶部显示：

- 已保存 · 12 秒前
- 最近自动恢复点 · 今天 21:35
- 最近 WebDAV 上传 · 昨天 23:10

### 4. 插件管理减少重复入口

目前“插件中心”和“设置 → 插件”都能做部分启停。建议明确分工：

- 插件中心：发现、打开、启停。
- 设置 → 插件：权限、导入导出、删除、高级信息。

### 5. 危险操作统一设计

现在删除插件、恢复备份、清空数据等确认框文案和交互由各处直接 `window.confirm` 实现。建议统一 `confirmDialog()`，支持：

- 危险等级。
- 操作对象摘要。
- 是否可撤销。
- 明确主按钮文案。

## 推荐下一个版本：v0.12.0「可配置工作台 + 同步安全」

如果只能选一个主方向，建议不要继续加十几个散功能，而是做“用户自己的工作台”。

### S 级：可配置首页 / 工作台

- 首页组件可显示/隐藏、拖拽排序。
- 组件候选：今日任务、今日时间块、下一事件、收件箱、番茄、考试倒计时、周进度、快捷操作。
- 用户可设置默认首页和模块密度。
- 工作台配置进入 `settings.ui.dashboard`，后续插件也可以注册小组件。

这会直接把“更多设置按钮自由度更高”升级成“整个首页都能由用户决定”。

### S 级：正式 schema migration

先把数据演进基础打牢，避免 v0.12 以后继续靠分散 `??=` 维护兼容。

### S 级：WebDAV 双向合并与冲突收件箱

让多设备真正可用，而不是仅作为手动备份。

### A 级：插件安全边界 2.0

iframe / Worker + 消息桥 + 网络域名白名单 + 安装权限摘要。

### A 级：设置项接入命令面板

用户可以直接搜索“背景”“提醒”“同步”并跳转，不需要先打开设置。

## 不建议下个版本优先做的事

- 不建议先继续增加主题数量：现在 9 套已经够多，信息架构收益更大。
- 不建议先增加更多独立时间视图：已有视图数量已经很高，应该先解决“用户如何选择和隐藏不用的视图”。
- 不建议在插件隔离完成前开放公开插件市场。
- 不建议在 WebDAV 合并前做自动后台双向同步，否则覆盖风险会被放大。
