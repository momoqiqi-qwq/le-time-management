# U-Time v0.104.0

## 更新内容

### 学习通待办补第五档「已提交待批改」（`chaoxing-notify` 2.12.2 → 2.13.0）

需求（用户）：「待办作业已提交，但请将已提交但老师未批改的作业也添加进去」——
截图那条 `作业:《智慧消防专业英语》2026年9月16日作业` 已经交了、成绩还没出，
但待办作业页里完全找不到它。

根因不是漏了筛选，而是**这条通知压根没有「结束时间」行**：

```
课程名称：智慧消防专业英语
作业名称：2026年9月16日作业
开始时间：2026-09-16 21:24          ← 到此为止，没有结束时间
```

而原有四档全部建立在「正文能解析出 `结束时间/截止时间：YYYY-MM-DD HH:MM`」上
（`withDue()` 先 `filter(n => n.dueText)`），所以这类作业四档都不进，
**连提交状态都不会被探测** —— `probePendingWorks()` 的队列只从 `todos()` 和 `lateAll()` 里取，
两个列表它都不在。老师发布作业时不设结束时间相当常见：真实账号 54 条带作业附件的通知里，
**44 条只有开始时间**，全部未被探测。

### 一、新增第五档，口径收得紧

`noDueWorks()` / `recentNoDueWorks()` / `gradingNoDue()`：

- **只探、只列近 `NO_DUE_GRADING_DAYS = 60` 天发布的**。那 44 条里只有 1 条是本学期的，
  其余 43 条是 4～7 月的上学期遗留 —— 不设边界就等于为一条新作业去多打 44 次请求，
  再把上学期的作业灌进待办页。
- **只列探到已提交（作业页是查看页）的，未提交的不收**：没有截止时间就判不出
  「未截止 / 已逾期」，混进前四档只会让那两档的语义失真。
- 认不出发布时间的按近期放行（`noticeTimeMs()` 返回 `null` 时不淘汰），
  避免把还在等的作业静默丢掉；排序上这类垫底，等得最久的排前面。
- **不计入侧标「待办作业 N」**：那个数字仍是真正待处理（未提交）的条数，
  交完的活不混进待办主计数。顶部 KPI 与分区各自带这一档的条数，可单独点选。
- 卡片那行没有截止时间可写，改成交代发布时间：`无截止时间 · 发布于 2026-09-16 21:24`。

### 二、探测队列

`probePendingWorks()` 的每轮预算从「未截止 ≤6 + 逾期 ≤4」扩到再加「近期无截止 ≤4」，
逐条串行不变。顺带修正了函数头上那句「每轮最多探 6 条」的旧注释（实际早就是分批）。

⚠️ 这一档**不会随成绩公布自动清空**：平台出分后作业页仍是查看页，本机信号翻不回来
（`workStatus` 探到就不重探）。批完了用卡片上的「移除」收掉，只影响本机、不动学习通。
这条限制写在分区 tooltip 和代码注释里，不假装会自动消失。

### 三、清单文案

manifest 的 description 里那句「待办作业分…三档」早已与实际不符（实际四档），
一并改成五档并写明第五档的适用条件与 60 天边界的理由。

## 影响范围

只影响 Windows 与 Android 两端的「学习通」插件；小程序端是独立的原生实现（`miniprogram/core/chaoxingCore.js` 与插件页），本版未改动，不含第五档。
`pluginCatalog.js`（桌面 + 小程序）由 `sync-plugins.js` 同步到 2.13.0。
网络正常、且通知里带结束时间的作业，四档行为与升级前完全一致。

## 数据迁移

无。`workStatus` 的取值与结构未变（只是多探了一批新 workId），
`ignoredIds`、`readOverrides`、`filter.todoSec` 都不受影响；老数据没有新键时行为同升级前。
