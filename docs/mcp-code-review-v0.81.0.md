# U-Time v0.81.0 代码优化审查

日期：2026-09-20

## 结论与范围

有值得优化的地方。建议先处理 **3 个交互边界问题**，再减少拖拽过程中的重复计算；暂不进行大规模重构。

本轮重点检查 `le-time-management/src/toolbarDrag.js`、`shell.js` 的工具栏/设置入口/插件卡片，以及公共动效和相关测试。这是局部审查，不是全仓库、Rust 原生端或全部插件的完整审计。

- 探针复用模拟 DOM，并调用真实模块或从源码提取的真实处理函数；**不等同于真实浏览器、桌面 WebView 或 Android 真机验证**。
- 下列路径均相对仓库根目录，行号对应本次审查快照。

## 优先处理的项目

### R1 · 工具栏键盘换位到边界时，没有拦截浏览器快捷键

**位置：** `le-time-management/src/toolbarDrag.js:211–220`，尤其是 215–216 行。

**原因：** `onKey` 在目标位置越界时先 `return`，后面的 `event.preventDefault()` 不会执行。

**触发条件：** 焦点位于第一个可排序按钮，按 `Alt+←`；或位于最后一个按钮，按 `Alt+→`。单个可排序按钮也会遇到此问题。

**影响：** 不能换位时，按键仍会交给宿主处理。在支持这些快捷键的浏览器/WebView 中，有意外后退或前进的风险。应用本身也将浏览器后退接入了视图历史（`shell.js:1461–1468`）。本轮确认了默认行为没有被拦截，未进行真实浏览器导航复现。

**探针结果：**

| 场景 | 是否调用 preventDefault |
|---|---|
| 首项 Alt+← | 否 |
| 末项 Alt+→ | 否 |
| 可以成功换位的 Alt+→ | 是 |

**建议：** 确认目标是本工具栏内有效、可用的排序项后，先拦截默认行为，再判断是否越界。边界操作只需保持原顺序，不应写盘或播放换位动画；工具栏外的正常后退快捷键不要拦截。

**应补测试：** 首项向左、末项向右、单项列表、工具栏外快捷键；检查顺序、提交次数与 `defaultPrevented`。

### R2 · 插件卡片的键盘事件会抢走内部按钮的操作

**位置：** `le-time-management/src/shell.js:1330–1337`、`1363–1372`。

**原因：** 卡片的鼠标点击处理会排除内部按钮，但 `onkeydown` 没有对应的目标过滤。内部按钮的 Enter/Space 事件冒泡到卡片后，卡片会 `preventDefault()` 并进入插件。

**触发条件：** 插件已启用且有可打开视图，焦点位于卡片内部的“关闭插件”等按钮。

**影响：** 本来要操作开关，可能变成打开插件页面。开关在 `click` 中的 `stopPropagation()` 不能阻止更早的 `keydown` 被父卡片处理。

**探针结果：** 将 Space 事件的 `target` 设为内部 BUTTON、`currentTarget` 设为父卡片，实际处理函数仍阻止默认行为，并调用了 `switchTo("plug:review-plugin")`。这验证了事件处理函数的缺口，未模拟浏览器完整的键盘激活流程。

**建议：** 卡片键盘入口仅处理卡片自身获得焦点的情况，例如检查 `event.target === event.currentTarget`；内部按钮继续使用自身的原生键盘行为。

**应补测试：** 卡片自身 Enter/Space 可打开；内部开关 Enter/Space 只切换一次、不额外导航；内部“打开”按钮仍正常工作。

### R3 · data-motion="off" 在公共动效逻辑中没有被完整遵守

**位置：**

- `le-time-management/src/motion.js:23–37`、`47–64`
- `le-time-management/src/styles/interactions.css:52–57`
- 实际使用处：`le-time-management/src/shell.js:202–212`、`toolbarDrag.js:117–121`

**原因：** 全局 pointerdown/click 处理只检查 disabled / aria-disabled，没有检查自身或祖先的 `data-motion="off"`。CSS 的 `.motion-pressing` 两条选择器也缺少对应排除条件。

**探针结果：** 对明确标记 `data-motion="off"` 的按钮派发 pointerdown 后，仍添加了 `motion-pressing`，并生成了 1 个 `.motion-ripple` 节点。

**影响：** 声明关闭动效的控件仍被加入动效处理，也产生不必要的 DOM 操作。拖拽期间的动效隔离与移动端悬浮按钮的预期不完全一致。

**建议：** 在公共动效入口统一判断自身/祖先的关闭标记，并让 CSS 同样遵守该约定；减少动效模式也应尽量跳过没有意义的计算。只跳过反馈动画，不影响按钮的业务点击。对于拖拽开始前已添加的按压类，还需要一致的清理或样式抑制。

**应补测试：** 自身 off、祖先 off、鼠标和键盘点击、拖拽中切换标记、减少动效模式。

### R4 · 拖拽停住后仍逐帧计算，可改为按需调度

**位置：** `le-time-management/src/toolbarDrag.js:9–14`、`93–107`、`153–154`。

**原因：** `frame()` 在会话激活期间不断申请下一帧；`update()` 即使指针没有移动，也会重复写副本 transform、遍历按钮、读取几何和计算样式。

**模拟探针：** 3 个按钮，完成一次换位后不再发送 pointermove，连续执行 60 个模拟帧：

| 操作 | 次数 |
|---|---:|
| getClientRects | 180 |
| getComputedStyle | 180 |
| 相同副本 transform 写入 | 60 |
| 结束时仍等待执行的下一帧 | 1 |

按钮顺序在这 60 帧中没有变化。这些是模拟 DOM 中的调用次数，**不是实测 FPS、CPU 占用或耗电数据**，不能据此承诺具体性能提升。

**建议：** pointermove 只记录最新坐标，并在没有待执行帧时申请一次 rAF，合并同一帧的多次移动；没有输入或几何变化时不继续空转。松手仍同步处理最后坐标，取消/卸载时清理帧与监听。可缓存参与项，但必须考虑布局或节点变化时的失效，不能为了省读取牺牲正确性。

**应补测试：** 静止时不重复排帧、高频 pointermove 每帧最多一次更新、最后一次移动后立即松手仍正确提交、取消/缩放/节点失效后的清理。

## 后续优化，不建议与上述修复一起大改

### 补充真实浏览器交互回归

当前 `scripts/test-toolbar-controls.mjs` 的模拟 DOM 是有用的逻辑回归，但还有明确边界：

- `Target.fire()` 不模拟完整的捕获/冒泡和浏览器默认行为（36–40 行）。
- `cloneNode()` 实际是浅层模拟（65 行）。
- pointer capture 是空方法，动画只记录参数，几何不反映实际 CSS transform（53–70 行）。

保留这些快测，另补少量浏览器集成用例：真实键盘、嵌套窗口按钮、拖动后的 click、防丢失 capture、80%/125%/150% 缩放和减少动效。无需把所有源代码结构守卫全部删除或重写。

### 加固拖拽副本的可访问性

`toolbarDrag.js:131–138` 深克隆工具项后，只把根元素设为 `aria-hidden` 和 `tabindex=-1`。窗口控制组含内部 BUTTON（`shell.js:278–281`），这些后代没有被显式移出焦点序列。

建议为视觉副本使用 `inert`，并按目标 WebView 的兼容性处理后代焦点与重复 ID。这是静态结构风险，本轮未验证真实 Tab 导航路径。

### 按职责逐步拆分 shell.js

当前 `shell.js` 为 1622 行，同时承担工具栏、侧栏、设置弹窗、快捷浮窗、插件市场等职责。建议在上述小修完成后分批提取模块，而不是一次性重写。

较好的第一步是把顶栏顺序归一化提取为可直接导入的纯函数。当前测试依赖截取 `shell.js` 文本并用 `new Function` 执行（`test-toolbar-controls.mjs:7–12`），会被无关的源码组织变化影响。

组件化时可统一管理拖拽控制器、observer 和全局监听的 dispose。当前启动路径只看到 `main.js:46` 调用一次 `renderShell`，所以**不能据此宣称正常运行时已经存在持续泄漏**。

## 已有设计建议保留

- 顶栏与左下操作条共用拖拽实现，避免两套行为逐渐分叉。
- 排序完成后才持久化，没有在每次 pointermove 中写用户数据。
- 取消回滚、减少动效和界面缩放已纳入逻辑回归。
- 设置按钮复用既有设置面板，没有增加另一套配置状态。
