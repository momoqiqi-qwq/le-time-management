## 修复：应用内打开网页白屏

- 开启「应用内打开网页」后点链接，新窗口只剩一片空白、应用整体卡住：`open_internal` 原先是**同步** Tauri 命令，在主线程的 IPC 回调里直接建窗，而 WebView2 控制器创建完成的回调同样只能由主线程事件循环派发 —— 再入即死锁，窗口框画出来却永远拿不到内容。改为 `async` 命令后建窗请求经事件循环代理，主线程照常泵消息（与教务导入窗口 `school_import_open` 同一条路径）。
- Android 侧同一函数受益：同步命令在移动端也占用主线程，改 async 后行为与教务窗口一致。
- 无数据迁移，链接可达性回退逻辑（建窗失败即交系统浏览器）保持不变。

## 影响范围与限制

- 小程序主改；Windows/Android 除「应用内打开网页白屏」这一条 Rust 命令修复外，仅同步产品/插件版本、目录与共享模型构建校验，不覆盖其他任务的源码工作。
- 现有存档与额外设置保留，旧存储键作为迁移回退副本保留；无自动清空、无预置示例任务。
- 不移植教务网页登录/OCR、任意网页内嵌、系统常驻/悬浮窗、后台可靠响铃与桌面 AI 自动执行；不新增产品 npm 运行时依赖。
- 未上传、提审或发布小程序，也不读取上传密钥。
