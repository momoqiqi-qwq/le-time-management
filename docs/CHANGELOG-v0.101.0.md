# U-Time v0.101.0

## 更新内容

### 左下角通知堆叠（`src/notifyStack.js` 新增 + `styles.css`）

多条横幅提示过去会一直往下堆，攒到七八条时最后一条被挤出屏幕，用户根本看不到新来的那条。

- 桌面端把同一个容器里的多条横幅**叠成一张**：后面那张只露出 11px 的边，鼠标移上去（或键盘焦点落进去）
  才向上散开。容器是贴底定位的，所以只有「后面那张」向上退，最前面那张一动不动。
- **分工刻意切成两半**：CSS 负责全部视觉与动画（折叠量 = `露出的边 - 自身高 - 间距`），
  JS 只喂 CSS 算不出来的两个量 —— 每张卡的真实高度 `--item-h` 和「现在该不该折叠」`is-stacked`。
  `--item-h` 缺失时按 0px 兜底退化成不重叠：宁可摊平，也不要叠出错位。
- **常驻卡（`[data-pin]`）永远不参与折叠**。它带着要用户按的按钮，被盖住就等于按钮消失。
  打标记的只有两处：`ui.js` 的 `toast()`（`ms: 0` 隐含钉住，要「常驻但允许被盖」得显式写 `pin: false`）
  与更新进度卡。只要容器里有一张常驻卡，整列摊平。
- **触屏设备整套不参与**：折叠靠 hover 才展得开，手机上「叠起来」等于「看不到」。判据写在
  CSS 的 `@media (hover: hover) and (pointer: fine)` 里，只问指针不问宽度 —— 桌面窗口拖窄了
  鼠标照样能 hover 回来，没有藏东西的风险。
- **开关在「设置 › 界面与交互」的「通知叠成一张（鼠标悬停展开）」**，默认开。实现走系数而不是
  删规则：`:root[data-notify-stack="off"]` 把 `--ns-fold` 归零，折叠公式整条乘出来就是 0，
  所以拨开关当场就变，不必等卡片重建或重排。老存档里没这个键 ⇒ `!== false` 的约定让它落到新默认，
  不会被误判成「用户关过」。开关只跟「启动窗口大小」那一组一样在桌面出现 —— 触屏设备上 CSS 那条
  媒体查询整条不生效，摆了也拧不动什么。
- 挂 `ResizeObserver` 让容器此后任何一次尺寸变化都重算，卡片增删、内容换行都靠它刷新。

### 更新流程改成「一张会变的卡」，带 git 风格下载读数（`src/updateChecker.js`）

原来左下角只在「发现新版本」时弹一张卡，点下载之后进度只在设置页里，用户点了「立即升级」就没了下文。

- 现在左下角的卡分两种：`version`（发现新版本）与 `live`（下载中 / 已下载完 / 失败 / 安装中）。
  **live 优先** —— 真的在下载时，进度就是唯一要看的东西，再留一张版本卡在后面只会把它的
  「立即升级」按钮藏进堆叠里。
- **同种类只改文字、绝不重建节点**：下载进度一秒刷好几次，重建会把入场动画重放一遍，
  卡片看着就一直在「跳」。
- 进度行照 git 自己的写法（`12% (16.42 MiB/150.68 MiB) | 1.08 MiB/s`）而不是画进度条 ——
  数字在跳才看得出「真的在下」，静止的进度条反而像卡住了。两个退化是刻意的：
  `total` 未知时省掉百分比只报已下体积（猜分母会让进度从 30% 跳回 90%）；
  速率没采到第二个点时显示 `-- B/s` 而不是 `0 B/s`（0 读起来像卡住，实际只是第一个采样点）。
- **速率由前端算**：Rust 侧只报 `received/total`。取 α=0.35 的指数滑动平均、200ms 最小采样间隔
  —— Rust 按总量切约 200 步长发事件，中间抖一下瞬时速率就能差几倍，直接显示会跳成筛子。
  每次下载开始 `reset()`，否则上一次的平均值会接到这一次头上先跳一段假数字。
- **`errorStage` 决定打扰不打扰**：新增 `check` / `download` / `install` 三段标记。检查失败
  （离线、GitHub 限流）继续静默，只在设置页回显；下载与安装失败才弹卡，卡上带「重试」
  （下载失败且 `asset_url` 还在就续一次，否则重新检查）。
- 「发现新版本」卡的闸门从「点亮时查一次」挪到**渲染时查**：卡片是常驻的，中途用户点了
  「忽略此版本」或关掉「弹窗提示」开关，都得当场把已经亮着的那张收掉。
- 容器被外部摘掉（测试直接 remove 节点、热重载换了 body）时连「已经建过卡」的印象一起清掉，
  否则往新容器里什么都不塞 —— 屏幕上什么都看不到且不报错。

### 二进制落盘 `tide.assets.saveBase64`（Rust 新命令 + 宿主 API）

`save_download` 按 UTF-8 文本写入，docx / pdf 这类二进制走它直接坏掉。新增 `save_download_base64`：
收 base64（与 `http_fetch` 的 `binary: true` 同格式，STANDARD 字母表），解码后写进同一个下载目录，
重名追加 ` (n)` 的逻辑与原命令共用（抽成 `save_to_download_dir`）。
插件侧对应 `tide.assets.saveBase64(name, base64)`，仍需 `ui` 权限。
`plugin-guide/plugin-development.md` 补了用法，并明确**不要**再拼 `data:` URI 走 `<a download>`
（WebView 里静默失败）。

### 门户附件改为真落盘（`cppu-notify` 1.23.0 → 1.24.0）

- 附件下载从「拼 `data:` URI + `<a download>` 点击」改成 `tide.assets.saveBase64`，成功后提示里直接给落盘路径。
  顺带删掉了那份按扩展名硬编码的 `mimeOf()` —— 走真落盘之后 MIME 没有意义了。
- **新增一道拦截**：门户票据过期时下载链接会 **200 返回一张登录页**，不拦就会存下一个打不开的「附件」。
  现在按 `contentType` 判出 HTML 并直接报「门户会话已过期，请重新打开插件登录后再下载」。
- 失败不再悄悄降级成「打开附件链接」，而是把原因说清楚。

### AI 对话回答排版收口（`ai-chat` 0.2.0 → 0.3.0）

按 v0.100.0 的真机截图漏法逐条补的：

- **正文里不再出现内部 id**：截图上出现过「（id=b_hrc882934078e）（id=b_hrc882934078e）」——
  模型把快照行的尾巴抄了两遍。新增 `tameIds()`：同一行已写了标题就连括号整段丢；认得这条但行里没提
  标题就换成标题（括号成对时保留）；对不上号（编造的或已删的）直接丢。映射表由 `snapshot()` 顺手填，
  关掉「带本机数据」时表是空的，效果等于一律抹掉。编造该拦的地方仍在建议块（`normalizeSuggestion` 标红）。
- **序号列表**：模型爱用「1.」「1、」「1）」「1）」，之前全糊成一段。现在都收进 `<ol>`，
  但 `1.5 小时` 不算列表 —— 点号后必须跟空格。
- **小标题**：提示词让它用「一、二、」分块，那是读出来的序号所以要连着留（`### 标题` 只取文字），
  渲染成加重的 `.sec`；`[文字](网址)` 一并收掉只留文字。
- **首行摘要**：第一行确实很短（≤60 字）才做成带左侧色块的结论 —— 模型偶尔第一行就是一坨 150 字的整段，
  那样加粗反而更糊。
- **提示词加七条输出格式规则**（第一行只写结论且不加「结论：」前缀 / 最多 3 块 / 禁内部 id 与系统词 /
  不复述问题 / 数数题只能报「至少 X 条，另有 N 条未列出」/ 小标题只用中文序号 / 数据不够时只写一句），
  并把「尽量短」改成明确的结构要求 —— 回答显示在手机屏幕的窄气泡里。

### 警大教务四个页面自带自动登录（`cppu-notify` 1.24.0 → 1.25.0）

从侧栏直接点「警大创新学分」（以及选课 / 请假 / 警大学分）会甩一句「教务登录态未建立：请先在
「警大通知」里完成登录」，即使密码早就存进密钥库了。根因不是缺功能：门户 SSO 的三级自动登录
（恢复 Cookie → 静默续期 → 密码 + 验证码识别）整段写在通知视图的 `render()` 里，而四个教务视图的
`mountJwView` 只做了 `jwRestoreCache()`（读数据缓存），**从不建立登录态**，于是 `jeLoad` 在
`!state.sid` 那一步直接短路 —— `ensureJwSession()` 那条全自动换票链路根本没机会跑。
对比「警大一卡通」视图是完全自举的，所以它没这个毛病。

- **登录代码收成一份**：把 `autoLogin()` 的第②级（保存的密码 + 验证码 OCR，`AUTO_ATTEMPTS=6` 那段）
  抽成 UI 无关的 `passwordAutoLogin()` —— 只返回成功/失败，不碰 `el`，失败原因留在 `loginHint`。
  通知视图的 `autoLogin()` 变成薄壳，第①③级（`loadPage` 探票、`paintLogin` 兜底）原样保留。
- **新增 `ensureJwLogin()`**：恢复密钥库 Cookie → `ensureJwSession()` 换票 → 不行就
  `passwordAutoLogin()` 再换一次票。`jeLoad` 与 `loadJwTerm` 一律走它，所以从哪个入口取数都自带引导。
  并发调用合流（一个模块级 promise），连开两个教务视图不会并排跑两套验证码登录；
  **只合流、不缓存结果** —— 点「刷新」时该再试一次，别拿着上次的 `false` 一直不回本。
- **人工兜底复用同一张登录卡**：`paintLogin()` 加 `opts.onDone`，教务视图摆出来的那张登完回它自己那一页
  （重挂视图继续拉数据），不再跳去通知列表。`prepareLoginForm()`（抓 execution + 一张验证码）也抽出来共用。
- 顺带修正两处过时文案：`jeLoad` 那句「请先在警大通知里完成登录」（改完就不成立了），
  以及 `plugin-guide`（1.3.2 → 1.3.3）里「手动输入验证码完成 SSO 登录」—— 验证码早就是自动识别的。
- **课程表插件的警大教务导入不在这次范围内**：它开的是真实 WebView 窗口，那边的 cookie 存储与
  `tide.http` 的 cookie jar 互不相通，插件里存好的会话递不进去，做不到自动登录。

`scripts/test-cppu.mjs` 新增 §13 五条：冷启动只恢复门户 Cookie 也要建好教务会话、并发引导必须合流、
存过密码就要自己去跑满六次换图重试（认不出如实报未登录）、什么凭据都没有时不许白抓验证码、
以及反向断言旧文案不再出现。**这条冷启动路径此前完全没有测试覆盖**，正是这个 bug 溜过去的原因。
测试的 mock 顺带补了 `tide.storage` 的默认值、`tide.vault.del` 和一个解不开图的 `Image`（用来把
OCR 逼到重试上限）。

### 新插件「GitHub 文档」`github-readme` 1.0.0（追踪仓库 README 的更新）

填 `owner/仓库名`、粘仓库网页链接、或粘 `git@github.com:o/r.git` 都能加入，点开就是按 GitHub 风格渲染的
README 正文；README 有新提交时作为消息推出去，可与微信推送插件联动。一期**只读 README 这一个文件**，
不含 release / issue / 文件树，也不支持 Gitee。

- **日常轮询一个 `api.github.com` 请求都不发**。匿名 API 限流只有 60 次/小时，追十几个仓库轮几轮就撞墙。
  改成两条不吃限流的路：变更靠 per-path 的提交订阅 `github.com/<o>/<r>/commits/<分支>/<路径>.atom`，
  正文靠 `raw.githubusercontent.com`。API 只在「添加仓库」那一刻用一次 —— 为的是拿回 README 的**真实文件名与
  默认分支**（`readme.md` / `README.MD` / 放在 `docs/` 下都实测存在，猜不出来）。被限流或网络不通时
  只在对应仓库上标一行中文原因，其他仓库照常抓。
- **首次加入只播种、不广播**：把当前 Atom 的 sha 存进已知表（上限 40 条）。不播种的话第二轮会把整条
  提交历史当成新提交推出去。
- **一轮只广播一次**：多个仓库攒下的新提交合成一条 `notice:new`（`items` 截到 5 条），省 PushPlus 频次；
  `emit` 包在 `try` 里，**广播抛错不许影响抓取本身落盘**。未读计数只服务界面，绝不参与广播差分 ——
  差分那表只在点开卡片时才写，拿未读做差分等于每刷新一次就把没点开的旧提交重推一遍。
- **渲染**：表格（含 `:---:` 列对齐）、围栏代码块、任务清单、嵌套列表、页内锚点目录、徽章图片；
  相对路径分别改写成 raw（图）/ blob（文档）绝对地址；宽表格在手机上横向滚动而不是压成一团。
  两处是环境差异逼出来的：`http:` 图源会被 APK 的 WebView 当混合内容**静默**拦掉，所以降级成可点链接；
  `<picture>` 的 `media="(prefers-color-scheme: dark)"` 读的是系统主题，而应用内深色看 `data-theme-mode`
  （两者可以相反），所以拆成两个带主题类的 `<img>`，交给宿主选择器决定显示哪张。
- **XSS 处理按「不可信输入」对待**：整份正文先整体转义，之后只有本文件自己生成的标签才是活的。裸 HTML 走
  「标签 + 属性」**双白名单**（README 里 `<picture>` 换深浅色 logo、`<div align=center>` 排徽章太常见，
  全转义会把首屏变成一坨可见源码）；`style` 与一切 `on*` 属性不在表内、永远剥掉，`javascript:` / `data:` /
  `vbscript:` / `file:` 协议一律拦；白名单外的标签按源码显示是刻意的（GitHub 会渲染出来，我们不渲染）。
  生成的标签先经 `hold()` 存成占位符、最后一步才回填，否则「裸 URL 自动成链」会把已经拼好的 `href` 再吃一遍。
  Atom 的实体只解一趟 —— `&amp;lt;` 二次解码就会变成活的 `<`，那是 XSS 入口。
- 随插件带 `scripts/test-github-gfm.mjs`（渲染器 60+ 条断言）与 `scripts/test-github-readme.mjs`
  （地址解析 / README 元信息 / Atom 解析 / 首轮只播种 / 一轮一广播 / 载荷契约 / items 截断 /
  广播抛错不吞抓取 / 限流与网络降级 / 落盘恢复）。图标由 `gen-plugin-icons.py` 生成，
  桌面 + 小程序各一份 PNG。

## 影响范围

Windows 与 Android 两端：通知堆叠、更新卡与 `saveBase64` 都在共用前端；`save_download_base64` 是
Rust 侧新命令，两端同时生效。`src/uiPreferences.js` 新增 `notifyStack` 一项偏好（默认开）并接进
「设置 › 界面与交互」与设置搜索索引，桌面独有；小程序端不受影响（`ai-chat` / `cppu-notify` 在小程序
标记为 `unavailable`，本次只同步了 `pluginCatalog.js` 里的版本号）。`pluginCatalog.js`（桌面 + 小程序）
由 `sync-plugins.js` 重新生成。新插件 `github-readme` 清单里 `windows` / `android` 都是 `full`、
`miniprogram` 直接标 `unavailable`，所以小程序侧只多一条插件目录记录和一张图标 PNG，没有可执行代码；
`src/settingsSearchIndex.js` 加了一行设置搜索词，服务于「通知叠成一张」那个桌面开关。

## 数据迁移

无。新增的 `notifyStack` 偏好走 `normalizeUiPreferences` 的 `!== false` 约定，老存档里没有这个键就落到
默认「开」；`settings.update.skipVersion` 等既有键的结构与含义未变；更新状态里新增的 `errorStage`、`speed`
只活在内存态，不落盘。
