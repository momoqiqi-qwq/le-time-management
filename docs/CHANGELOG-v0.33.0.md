# Le时间管理 v0.33.0

## 改了什么

三条需求（用户反馈）+ 一处手机端反馈：

> ① 在设置个性化里面添加彩色滑块按钮，打开后像图中这样
> ② 每次打开的默认主界面扩大一些，可以在总设置中设置每次打开的默认界面大小
> ③ 课表界面无法使用滚轮上下滑动
> ④（手机端）导入课表后卡在教务窗口里退不出去

### 一、课程表：新增「彩色课程块」滑块

「我的 → 个性化配置」最上面多了一行**彩色课程块**滑块（开关型控件，不再是原生 checkbox）。

- **打开后**：每门课变成一块**实色卡片**，配浅色文字，观感对齐原版时光课程表。
- **配色自动分配**：没手动选过颜色（`color` 还是默认 0）的课，按**课程名散列**取色 ——
  导入一张教务课表就自动花起来，不用一门门点。同一门课名称稳定，颜色就稳定；手动在课程编辑里
  选过的颜色**优先**，彩色模式下也不会被覆盖。
- **关闭时**（默认）：保持原来的浅色描边样式，老用户的观感一点不变。

调色板是**刻意不跟随主题**的 8 档实色（蓝 / 青 / 琥珀 / 紫 / 红 / 深青 / 绿 / 靛）。
因为它是按「白字压在上面 ≥4.5:1」挑的，而主题强调色在深色模式下会被**提亮** ——
拿它做实色底，白字只剩 2.4:1，正是 v0.31.0 修过的那类缺陷。
`scripts/test-schedule.mjs` 现在会**逐档校验 WCAG AA 对比度**，改色必须一起改测试。

顺带把「隐藏节次具体时间 / 隐藏日期」两个原生 checkbox 也换成了同一套滑块，面板不再一格一格的丑。
面板顶部加了一块**样式预览**（4 张示例课卡），拖动滑杆 / 拨开关会**实时**跟着变，
点「保存样式」才真正应用到课表。

### 二、课表界面滚轮上下滑动（bug）

> 症状：鼠标停在课表上时，整个页面**一点都滚不动**。

原因在 `.schedule-frame`：

```css
overflow: auto;
overscroll-behavior: contain;   /* ← 元凶 */
```

课表容器是**横向**滚动容器（周视图宽 630px 起步），但它纵向并不会溢出，高度跟着内容长。
`overscroll-behavior: contain` 把**两个方向**的滚动串联都切断了 —— 于是鼠标在课表上滚轮时，
浏览器发现「这个容器纵向滚不动」，又因为 `contain` 而**不往上层 `.plugview` 传递**，滚轮就凭空消失了。

改成只约束横向：

```css
overscroll-behavior-x: contain;   /* 保留横向不串联（防 Android 侧滑返回），放开纵向 */
```

实测（无头 Chromium 读计算样式，改前/改后各一次）：

| | `overscroll-behavior-y` | 课表色调 |
|---|---|---|
| 改前 | `contain`（滚轮被吃掉） | 16 个课程块**全是 tone-0**，一个色 |
| 改后 | `auto`（能串到外层滚动容器） | 散在 tone-0…tone-7 |

第二列顺带证明了第一条需求改前的真实状态：**整张课表只有一种颜色**。

### 三、启动窗口：默认更大，且可在总设置里选

- **默认值**：`tauri.conf.json` 的 `width/height` 由 `1280 × 820` 提到 **`1440 × 900`**。
- **新增设置**：「总设置 → 界面与交互 → 启动窗口大小」，6 个选项
  **跟随屏幕（默认）/ 小巧 1120×720 / 标准 1360×860 / 宽大 1600×1000 / 铺满可用区域 / 自定义尺寸**，
  旁边有「立即应用」可以马上试。
- **实现**：新增 `src/windowSize.js`，启动时（`src/main.js`）读偏好套一次。要点：

  - **跟随屏幕** = 当前显示器可用区域的 86%，小屏上自动收窄（`1366×768` → 约 `1175×660`），
    不会出现「开出来比屏幕还大」。
  - 所有模式都会**按显示器尺寸夹取**，超屏时退到「可用区域 − 24px」。
  - **每次都按设置开，不记忆手动拖过的大小** —— 需求就是「每次打开的默认界面大小」由设置决定，
    记忆上次反而会让设置看起来不生效。
  - 只走前端 `@tauri-apps/api/window`，**不动 Rust 侧**；Android / 浏览器调试环境直接跳过，
    失败一律吞掉，绝不拦住启动。

### 六、教务导入窗口：补上真正的「关闭」通道（手机端反馈）

> 症状：手机端导入课表后**退不出来**，点工具栏的「返回」也没反应。

根因：这个教务窗口在手机端**没有标题栏关闭按钮**，而注入工具栏里唯一的出口「返回」只是
`history.back()` —— 用户停在教务站**首屏**（没有站内历史）时它就是个**死按钮**，人被锁在教务页里。
桌面端有窗口自己的关闭按钮，所以一直没暴露。

补三条路：

- 工具栏加**「关闭」**按钮，走 `letime-import://close` 自定义协议，由 Rust 侧
  （`school_import_bridge` / `school_import_open` 的导航回调）真实 `window.close()`。
- 「返回」改成**有历史才 `history.back()`，否则退回关闭**（`history.length > 1` 判断），死按钮变成兜底出口。
- 适配器跑完最后一步会调 `notifyTaskCompletion`，Rust 侧**收到它就把教务窗口自动关掉**，
  用户不必自己去找按钮 —— 导入成功即收尾。

`scripts/test-school-import.mjs` 同时守三条通道（注入脚本可提取且语法有效、Rust 侧真有 close 分支、
完成即自动关窗），三条缺一条就红。
