# U-Time v0.102.0

## 更新内容

### 警大学分改按教务「我的学分」的课程模块分组（`cppu-notify` 1.25.0 → 1.26.0）

「警大学分」点开必修/选修/实践之后，模块组的标题是 `模块 14 · 2 门 · 已获得 2 / 修读 2 学分` ——
把成绩行的 `KCMK` 码直接当类名用了。根因是当时只拿到了码：教务在成绩视图里只回 `KCMK` 不回名称，
插件的字典快照 `JW_DD.KCMK` 是空的，宁可显示码也不编一个好听的类名，于是整屏都是「模块 NN」。

这次没有去补码表了事，而是把分组的数据源换掉了：**教务「我的学分」页面本身就是一行一个课程模块**，
而且自带四个学分数字，根本不需要客户端按码聚合。

- **新增数据源 `creditModule`**（`V_JWBZK_XKGL_XKQK`，菜单 学生服务 › 我的学业 › 成绩 › 我的学分，
  视图型功能，不需要回传 SELECT）。字段 `XFYQ` 学分要求 / `HDXF` 获得学分 / `YXXF` 在修学分 /
  `DXXF` 待修学分，**是右对齐补位到 15 字符的字符串**（`"             43.0"`），所以一律 `parseFloat`
  而不是 `Number`（`Number(" 43.0 ")` 能过，`Number("4 3.0")` 之类一抖就是 `NaN`，且补位串读起来
  根本不像数字）。
- **模块名走字典 `KCMKDM_1`**（31 条全量抄进 `JW_DD.KCMK`）。⚠️ **码与界面顺序毫无关系**：
  培养方案第一行「军事教育课程」是 `28`，「公共基础」是 `23`，「专业」是 `06`，`01` 是「自然科学」。
  按左栏列表顺序排 01、02 会全错 —— 这是本次实测的唯一收获，已写进注释与勘察笔记。
  字典里查不到的码仍原样显示「模块 99」，这条反向断言留着。
- **分组改成以模块行为准**，成绩行只负责挂到对应模块下面。于是多了两件原来看不到的事：
  培养方案里**一门课都还没有的模块也会露面**（`毕业论文 · 已获得 0 / 要求 6 学分 · 待修 6`），
  以前这些模块因为「没有成绩记录」整块消失，用户看不到自己还欠多少；
  以及 `在修 N` 这一档（课在修、成绩还没出）现在能显示出来。
- **方案外的模块码单独补一组垫底**，空码永远排最后 —— 重修、转专业这类成绩行不属于当前方案的任何模块，
  按模块行分组会把它们整门丢掉，所以保留兜底组，门数与学分仍按成绩行算。
- 「隐藏已修完」的语义跟着调整：它现在只过滤模块下面的课程卡，模块行本身（教务的计划进度）不跟着消失，
  隐藏掉的门数写在组标题和分节标题上（`已隐藏 1 门`），不悄悄少数据。
- **两套账核对过**：`ΣXFYQ = 170` 等于培养计划的 `KCZXF 157` + `SJKCZXF 13`；`ΣHDXF = 52.5`
  与按成绩行（34 门、`SFHDXF='1'` 求和）算出的已获得**完全相等**（必修 40.5 / 选修 12 / 实践 0）。
  所以顶部三张学分卡的算法原样保留，没有引入第二套口径。
- 顶部三张卡的算法、展开动画、`隐藏已修完` 开关的位置都没动。

`scripts/test-cppu.mjs` §12 的学分断言按真实形状重写：模块行 fixture 保留教务的补位字符串，
新增「模块名取字典」「码与界面顺序无关」「零成绩模块也要露面」「补位串要解析成数字」
「字典没这条码时不编名字」「隐藏门数要交代」等 8 条，并把取数接口断言扩到三个（培养计划 + 模块进度 + 成绩）。

### 内置插件的语义标签在深色模式下读不出（`cppu-notify` 深色覆盖 + `test-theme-contrast.mjs` §9）

教务视图的注释写着「一律用主题变量，深色模式自动跟随」，但 `.jw-tag.ok / .warn / .live` 三个语义色
仍是浅色硬编码（`#0B6B60` / `#8A6420` / `#B42318`），压在深色标签底上实测只有 **1.38~2.17:1** ——
`1 学分` 这种 10.5px 小字几乎读不出。宿主 `styles.css` 的「内置插件深色兼容层」白名单里没有
`.jw-*` / `.yk-*`，兜不住这一族，所以插件侧必须自带 `[data-theme-mode="dark"]` 覆盖。

- 深色下三个标签整组重给：底色改成同色相浅掺（比 `--panel` 更深，沿用 `--q*-bg` 的「深底亮字」路子），
  文字把强调色与 `--ink` 混亮，公式与宿主兼容层一致，16 套主题下都过 5.3:1。
- 一卡通的「已消费」三处（`.yk-status.warn` / `.yk-spent b` / `.yk-ledger-row.out b`）同样落在面板上的
  `#8A6420`（深色 2.6~3.0:1）只把文字混亮，不掺底色。
- **测试侧新增 §9 实算**：从插件源码里正则抓出这三条深色规则，按 `color-mix` 的通道线性插值真算出
  前景/背景再跑 WCAG AA，不达 4.5:1 就红；同时反向守卫浅色那三条**必须保留硬编码**
  （浅色 `--mint` / `--sun` 直接当文字色只有 2~3:1，正是同一族问题）。

## 影响范围

只影响 Windows 与 Android 两端的「警大教务」视图（`cppu-notify` 插件），小程序端该插件标记为
`unavailable`，不受影响。深色标签配色只改 `cppu-notify` 自带的样式块。
`pluginCatalog.js`（桌面 + 小程序）由 `sync-plugins.js` 重新生成插件版本号。

## 数据迁移

无。新增的 `creditModule` 只是内存态与 `jwCache` 里多一个键，老缓存里没有它时视图挂载会自动补拉一次，
不需要迁移；`jwState.expandedCredit`、`creditHideDone` 的结构与含义未变。
