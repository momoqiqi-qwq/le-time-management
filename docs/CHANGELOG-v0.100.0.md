# U-Time v0.100.0

## 更新内容

校园服务栏的「教务」入口升级为**带子菜单的父项**（`cppu-notify` 插件 1.22.0 → 1.23.0）。

- 原来「学生选课 / 学生请假 / 警大学分 / 创新学分」四个教务视图与 WebVPN、教育邮箱、学工等
  平铺在左侧「校园服务」栏里，现在收进「教务」父项下方：子项缩进一档、图标收小、
  去掉重复的「在 U-Time 内查看」副行。
- **父项整行的动作不变**：仍然用统一身份认证换一张一次性票据、免密打开教务首页。
  右侧新增一个独立的箭头按钮，只负责展开 / 收起。两者是 `.pp-side-row` 的兄弟而非父子
  （`<button>` 不能嵌 `<button>`），点箭头不会顺手把教务开进系统浏览器 —— 这条有断言守着。
- **默认展开**。这四个入口升级前本来就露在侧栏上，默认收起等于把已有功能藏到一次点击之后。
  展开态与侧栏的收起态一样只活在本次插件会话里，不落盘。
- 展开用仓库既有的 `grid-template-rows:0fr → 1fr` 手法；收起时同时置 `visibility:hidden`，
  否则折叠着的四个子项仍能被 Tab 走到。
- 窄屏（≤820px）侧栏是换行的 chip 流：父项不给 `flex-grow`（否则箭头会被推到行尾、
  与教务 chip 中间空一大段），箭头描边并给到 44px 触控区，子菜单整体独占一行、
  子项继续按 chip 换行。

### 明确不做的两项

按用户要求，教务导航里的「自习室查询」与「评分信息查询」**不接管**：这两个功能没有实测过的
`funcCode` / `funcId` / 表名，而教务 SPA 没有任何 URL 深链（`je-app` / `je-main` / `je-core`
三个 bundle 都不解析 `location.hash` 与 `location.search`），挂纯链接只会落回首页。
`scripts/test-cppu.mjs` 加了反向断言，防止以后被顺手加进去。

## 应用内「卸载 U-Time」入口（Android）

卸载原本只能在系统桌面 / 设置里做，应用内没有任何入口。这版在 **设置 › 关于** 里加了与
「软件更新」对称的一块：

- 新增 Android 原生桥 `AppUninstallerPlugin.kt`，用 `Intent.ACTION_DELETE` + `package:<包名>`
  把卸载交给系统的卸载程序；清单补 `REQUEST_DELETE_PACKAGES`（系统卸载 Activity 受这条权限
  保护，漏了 `startActivity` 直接抛 `SecurityException`，症状同样是「点了没反应」）。
  权限声明同时进 `tools/sync-android-native.js` 的补丁与 `SOURCES`，`tauri android init`
  重建 `gen/android` 后不会静默丢。
- 确认走应用内 `appConfirm`（危险色 + 20 秒无操作自动取消），文案先把代价说清楚：
  本机现有多少任务与时间块、卸载后无法找回、最终仍由系统弹窗确认。
- 旁边给一条退路：**导出完整备份**走 `save_download` 真落盘到系统下载目录
  （`<a download>` + blob 在 WebView 里不可靠），失败直接报错，不偷偷降级。
- 桌面端整块不渲染（Windows 走系统「应用与功能」）；浏览器调试模式仍渲染，
  因为手机 UI 的预览与录屏都跑在 :1420。

## AI 对话插件（内置，第 16 个）

`public/plugins/ai-chat/`，侧栏「AI 对话 内置 Alt+A」。

- 宿主新开 `tide.ai`（`chat` / `status`）与 `ai` 权限：复用「设置 › AI 与自动任务」里
  用户自己配的 Base URL / 模型 / Key，密钥只在 Rust 侧 AES-256-GCM 保险箱里，插件拿不到。
  上游非流式、一次 ≤24 条消息 / ≤60000 字符，两条限制都写进了插件开发文档。
- 提问前把本机数据压成快照一起发过去：逾期 / 今天到期 / 未来 7 天 / 更远 / 已完成，
  加今起 3 天的时间块，每条带真实 `id`；单段封顶 25 条、快照总长封顶 9000 字符。
  头部有「带本机数据」开关，关掉后提示词里一个本机字段都不出现（有断言守着）。
- **能收集其他插件推来的消息**：宿主在 `events.emit` 这一层把五家消息插件（门户 / 学习通 /
  学校通知 / 竞赛 / RSS）统一载荷的 `notice:new` 抄一份进跨插件队列（按
  `source|time|title` 去重、留最近 120 条），插件再并进自己的私有存储做到跨重启留存。
  抄收放在宿主而不是让订阅方自己蹲事件，是因为插件逐个加载，晚加载的听不到早加载插件
  在启动阶段广播的消息。新权限 `messages` 单独闸门。
- 回答里的整理结果停在**待确认建议列表**：`create-task / create-block / update-task / done-task`
  四种动作过白名单校验（非法 action 丢弃、编造的 id 当场标红、日期时间格式错就丢字段），
  逐条勾选才写库，写完给一条带撤销的提示（新建的删掉、改过的按原值还原）。
  写坏一条不连累其它条，失败原因标在那一行上。
- 吸底输入框靠 `.plugview` 的满高 flex 列实现，不建浮层、不挂 body、不读视口尺寸，
  安全区仍由宿主 `.view` 独家负责。

## 影响范围

仅 Windows / Android 的 `cppu-notify` 插件界面与插件清单描述。小程序端该插件标记为
`unavailable`，不受影响。

新增的卸载入口只影响 Android APK（含 Rust 侧新命令 `app_uninstall` 与清单权限）；AI 对话
插件影响 Windows / Android 两端，小程序端标记 `unavailable`。宿主新增 `tide.ai` 与
`tide.messages` 两个能力与 `ai` / `messages` 两条权限，对既有插件零影响。


## 数据迁移

无。`jwOpen` 是内存态，`jwCache` 的结构与键都未改动。

## 版本号说明

树里 `0.99.1` 是另一路在途改动（死代码清理）已占用的 patch 号，按「新功能走 minor、
不抢对方刚写的号」取 `0.100.0`。插件清单 `1.22.0 → 1.23.0` 同理取下一个 minor。
