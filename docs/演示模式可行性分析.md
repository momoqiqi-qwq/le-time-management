# 演示模式（Demo Mode）可行性分析

> 目标：给 Le时间管理 做一个**专门用于展示的模式** —— 自动打开、自动显示字幕、自动播放音乐、自动操作界面。
> 本文只做可行性论证与方案设计，**不含任何代码改动**。
> 基线：`86bbc58` / v0.53.0 ｜ 探查时间 2026-09-18

---

## 一、结论

**可行。** 而且这个仓库不需要从零搭 —— 四块关键拼图已经现成：

| 已有资产 | 位置 | 作用 |
|---|---|---|
| 视图跳转事件总线 | `src/shell.js` 监听 `tide:navigate` | 自动切换视图的现成驱动口 |
| 数据整体替换 | `src/store.js` 的 `replaceAll` / `batchChanges` | 注入演示数据 |
| 音效单一事实源 | `src/sound.js`（Web Audio 现场合成） | 音效**零资源文件** |
| 无头逐帧渲染链 | `创客比赛/tools/render-video.mjs` + `make-mp4.py` | 同一份脚本可再产出一版 mp4 |

另外 `src/main.js` 里已经留了话：「样例请做成显式入口（如『恢复示例数据』）」—— 演示数据的入口本来就是预期内的东西。

**真正的拦路虎只有三个**（都不是"能不能"，而是"必须做对"）：

1. **自动播放音频**会被浏览器内核默认拦截（Windows 与 Android 都是）
2. **演示数据不能污染真实数据** —— 包括托盘退出的存盘路径
3. **"自动操作"的保真度**必须分层，纯语义驱动做不出拖拽镜头

## 二、拦路虎 1：自动播放音乐

三端内核不同，默认行为也不同：

| 端 | 内核 | 默认行为 | 解法 |
|---|---|---|---|
| Windows 桌面 | WebView2（Chromium） | 无用户手势 → 带声播放被拦 | ① 由用户点一下「开始演示」（推荐）② `additionalBrowserArgs` 加 `--autoplay-policy=no-user-gesture-required` |
| Android | 系统 WebView | `mediaPlaybackRequiresUserGesture` 默认 **true** | 在 `MainActivity.kt` 显式置 `false` |
| 微信小程序 | 微信运行时 | `wx.createInnerAudioContext()` 不受此限 | 已可用（`miniprogram/core/taskReminder.js` 在用） |

**关键实测结论：`android/gradle/.../MainActivity.kt` 的 WebView 设置块里目前只有缩放两项**
（`setSupportZoom` / `builtInZoomControls` / `displayZoomControls`），
**没有** `mediaPlaybackRequiresUserGesture` —— 即 Android 上带声自动播放默认被拦。

### 推荐：不改原生配置，演示一律由「开始演示」按钮启动

一次真实点击就能解锁该文档的音频自动播放权（`AudioContext` 与 `<audio>` 都吃这一手），
解锁后整个演示期间不再需要手势。好处：

- 不用改 `tauri.conf.json` 的窗口配置，正常使用时的自动播放安全策略不受影响
- 不用改 `MainActivity.kt`，也就不用重跑 `sync-android-native.js`、不用碰 gitignored 的 `gen/android`
- 三端同一套逻辑

代价是不能"打开就响"。但在真机上"打开就响"本来就会被拦，而且演示场景里
**一个明确的「开始演示」动作反而是好事**（投屏/评委面前需要可控的起点）。

### 若坚持"打开就自动播"

- Windows：`tauri.conf.json` → `app.windows[].additionalBrowserArgs`。
  ⚠️ 该字段会**替换** wry 的默认参数，必须补回
  `--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection`（Tauri 2 schema 明确写了这点）。
- Android：`webView.settings.mediaPlaybackRequiresUserGesture = false`。
  注意这是**全局设置**，会影响正常使用时的所有媒体播放策略。

### BGM 素材问题

`sound.js` 只合成**短音效**（7 个内置音，最长 1.4 秒），**没有 BGM 能力**。背景音乐需要真实音频文件：

| 方案 | 体积 | 说明 |
|---|---|---|
| 打包自制循环 ambient 到 `public/demo/` | 3 分钟 128kbps ≈ 2.8 MB | 会进 `dist/` → 进 exe 与 apk |
| Web Audio 程序化生成 | 0 字节 | 只能做氛围音，做不出旋律 |
| BGM 只放在 Web 演示页 | 不计入应用包 | 走浏览器演示路线时可选 |

版权上建议自己合成/录制，`public/OPEN_SOURCE_NOTICES.md` 已有署名纪律，第三方素材要登记。

### ⚠️ 顺带发现的一个既有疑点（待验证）

Android 上 `mediaPlaybackRequiresUserGesture` 没关，而 `src/sound.js` 走的是 Web Audio。
**理论上**到点提醒的提示音在 Android 上可能解锁不了而变哑。
但应用内到处是点击，实际很可能早就解锁了 —— 这**不是断言，是需要实测确认的疑点**，
与演示模式无关，但值得单独验一次。

## 三、拦路虎 2：数据隔离

`store.js` 的写盘是 **350ms 防抖 + `api.saveData(state)`**；
`main.js` 里托盘退出还有 **`app-quit` → `saveNow()` → `quit_ack`** 的握手（Rust 侧最长等 2 秒）。

演示要注入假任务/假时间块，**下面三条路都要拦**：

1. 演示期间 `queueSave()` 直接跳过（不落盘）
2. 演示开始时把真实 state 快照进内存
3. 退出演示时恢复快照并正常存盘
4. **`app-quit` 握手期间若正在演示 → 先恢复真实数据再 ack**，否则托盘退出会把演示数据写进去

### 三档隔离强度

| 档位 | 做法 | 改动面 | 风险 |
|---|---|---|---|
| A（建议先做） | 内存快照 + 演示期拦截写盘 + 退出恢复 | 小 | 演示中途崩溃可能留下半覆盖数据 |
| B | 演示数据走**独立 state 分支**，`demoMode` 让 `getState()` 返回演示态，真实态只读 | 中 | 需要梳理所有 `getState()` 消费方 |
| C | 演示跑在**独立窗口 / 独立数据目录**（Tauri 侧支持） | 大 | 零风险，但要改原生 |

建议 P1 先做 A，并在演示入口显式提示"演示结束后自动恢复"；真要对外演示前再评估 C。

## 四、拦路虎 3：「自动操作」的保真度分层

### A 档 · 语义驱动（便宜、稳）

已存在的现成接口：

```
tide:navigate          切视图（quadrant / timeblock / market / plug:<id> …）
tide:open-settings     打开设置里的某一节
tide:command-palette   打开命令面板
tide:quick-capture     打开快速捕获
store.addTask / placeTask / addBlock / toggleTask …
```

配一个**合成光标**（跟随的 SVG 圆点 + 点击涟漪），让"自动操作"看起来像有人在点。
`motion.js` 已有涟漪/按压动画可复用。

**局限：做不出真正的拖拽。** 四象限卡片拖到时间轴那条「一拖即排」是片子的核心镜头，
纯语义驱动只能"瞬移"，观感差一大截。

### B 档 · 真指针驱动（贵、脆、但保真）

在真实 DOM 上合成 `pointerdown → pointermove → pointerup`。
**必须遵守 `shell.js` 的既有门槛**（已实测确认）：

- 桌面：移动 ≥ 6px 才进入拖拽
- 触屏：长按 240ms 进入（期间移动 > 8px 视为滚动意图）
- **拖拽激活后会吞掉紧随的 click**，且在**下一个宏任务**里才摘掉拦截
  ⇒ 合成驱动若不按此时序走，会顺带触发按钮自己的动作（比如把主题切了）

**建议：A 档做骨架，B 档只做 2~3 个「名场面」** —— 拖卡片排时间块、拖微信文字进窗口做捕获。
这两个恰恰是最值得看的。

## 五、时间轴引擎：用音频时钟做主时钟

字幕 / 动作 / 音乐三者同步，**不要拿 `setTimeout` 或 `rAF` 计数当主时钟**：

- `rAF` 在窗口失焦/最小化时被节流甚至暂停 → 演示"跳帧"
- `setTimeout` 会累积漂移

正解：**以 BGM 的 `AudioContext.currentTime`（或 `<audio>.currentTime`）为主时钟**，
每帧只做「当前时刻 → 该显示哪句字幕 / 该触发哪个动作」的查表。
掉帧后恢复会立刻对齐，而不是补播所有错过的事件。顺带白送进度条 / 暂停 / 重播 / 拖动定位。

数据结构大致：

```js
[{ at: 0.0, dur: 6.2, text: "信息散落 · 提醒缺位", action: { type: "navigate", view: "quadrant" } }, …]
```

**动作必须幂等且可跳转** —— seek 到 12.5s 时不能依赖"从 0 一路播过来"。

### 字幕渲染的仓库特有坑

- 窄屏（≤760px）**默认收起上下栏**（v0.52.0 沉浸式外壳），字幕浮层不能依赖 rail 几何
- Android 要避开 `--sat` / `--sab`（原生注入，**不是** `env()`）
- 浮层别用 `zoom` 定位，边距要 `calc(Npx / var(--ui-scale, 1))`
- 演示要**强制满动效**，但 `motion.js` 的 `reducedMotion()` 会读系统 `prefers-reduced-motion`
  ⇒ 演示期间需覆盖（`data-ui-motion="full"`）

## 六、最大的杠杆：一份脚本，两种产出

`创客比赛/tools/render-video.mjs` 已证明**无头 Chrome + CDP 逐帧渲染**在本机跑得通
（配 `make-mp4.py` 合成，24fps / H.264）。

于是同一份 `demo/script.js`：

- **实时演示**：应用内跑 → 现场可交互、可投屏
- **录制投放**：CDP 无头加载 web 构建 + 注入同一份 timeline + 逐帧截 → mp4

改一次文案两处生效。这比现有的 `三分钟视频动画.html`（**重画的假 UI**）强得多 ——
假 UI 会跟真实应用漂移，现在已经漂了不止一版。

⚠️ 无头环境的注意点：`--autoplay-policy=no-user-gesture-required` 在**命令行**里随便加
（与改应用配置是两回事）；`rAF` 在无头里会被节流，要用
`Emulation.setVirtualTimePolicy` 或逐帧 `Page.captureScreenshot` 手动推进时间 ——
`render-video.mjs` 里已有现成做法可抄。

## 七、三端取舍

| 端 | 结论 | 理由 |
|---|---|---|
| Windows 桌面 | ✅ **首选** | 驱动口齐全、屏幕大、投屏方便 |
| Android | ⚠️ 可行但性价比低 | 要改 `MainActivity.kt` 关手势限制 + 重跑 `sync-android-native.js`（`gen/android` 是 gitignored 生成目录）；手机演示不如电脑 |
| 微信小程序 | ❌ 不做 | 无 DOM 驱动、无事件总线、能力受限；建议只放"扫码看电脑演示" |

## 八、入口设计（"自动打开"）

| 入口 | 适用 | 说明 |
|---|---|---|
| `?demo=1` URL 参数 | 开发 / 录制 | 最干净，无 UI 侵入；`vite dev` 与 Tauri 都能用 |
| 命令面板命令 | 日常 | `commandPalette` 加一条「播放功能演示」 |
| rail 操作条按钮 | 日常 | `railActions.registerRailAction` 就是为「后续加按钮」准备的接口（v0.53.0 刚做） |
| 独立 exe | 对外分发 | ⚠️ 会**翻倍**构建与版本纪律成本，**不建议**初期做 |

## 九、版本与测试纪律

- 按铁律一，这是产品代码新增功能 ⇒ **minor +1 → v0.54.0**（当前 0.53.0）
- timeline 引擎是**纯逻辑**，可照 `scripts/test-rail-dock.mjs` 的模式做无头单测：
  排期顺序、seek 幂等、字幕不重叠不留空档、边界（0s / 末尾）
- 仓库现有 **48 个测试脚本** + 变异测试纪律，这块守得住
- 演示脚本的文案与时间轴要能 `--check`（防止改文案忘改时间）

## 十一、风险清单

| 风险 | 等级 | 缓解 |
|---|---|---|
| 演示数据污染真实数据 | 🔴 高 | 三档隔离，至少做 A；`app-quit` 路径必须覆盖 |
| Android 带声自动播放被拦 | 🟡 中 | 用「开始演示」按钮绕过，不改原生 |
| 合成指针驱动拖拽失效 | 🟡 中 | 只做 2~3 个名场面，其余走语义驱动；做降级（拖不动就瞬移） |
| BGM 版权 / 体积 | 🟡 中 | 自制素材 + 登记 `OPEN_SOURCE_NOTICES.md`；或放 Web 演示页 |
| 假 UI 与真应用漂移 | 🟢 低 | 复用真应用渲染，不做重画 |
| 演示脚本随 UI 改版失效 | 🟡 中 | 驱动口走事件总线/导出函数，不写死 DOM 选择器 |
